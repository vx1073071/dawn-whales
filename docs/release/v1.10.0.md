## Build Instructions

### Prerequisites

- **Node.js**: v22+ (v24 recommended)
- **npm**: v10+
- **OS**: Windows 10/11 x64 (for Windows installer)
- **Memory**: 8GB+ RAM (16GB recommended for build)
- **Disk**: 10GB+ free space

### Step 1: Install Dependencies

```bash
# Force development mode to keep devDependencies
set NODE_ENV=development

# Skip native module compilation if better-sqlite3 fails on Node 24
npm install --ignore-scripts

# If better-sqlite3 compilation is needed:
# npm rebuild better-sqlite3
```

### Step 2: Verify Build Prerequisites

```bash
# TypeScript check — must be 0 errors
npx tsc --noEmit

# Vite build — must succeed
npx vite build

# npm audit — must be 0 vulnerabilities
npm audit
```

### Step 3: Build Installer

```bash
# Windows NSIS installer
set NODE_OPTIONS=--max-old-space-size=8192
npx electron-builder --win --publish never

# Output: release/DAWN WHALES Setup <version>.exe
```

### Step 4: Generate SHA256 Checksum

```bash
# PowerShell
Get-FileHash "release\DAWN WHALES Setup 1.10.0.exe" -Algorithm SHA256 | Select-Object Hash | ForEach-Object { $_.Hash } > release\SHA256SUMS.txt

# Or using certutil
certutil -hashfile "release\DAWN WHALES Setup 1.10.0.exe" SHA256 >> release\SHA256SUMS.txt
```

### Step 5: Git Tag

```bash
git tag -a v1.10.0 -m "v1.10.0: Production release — R89-R94 finale"
git push origin v1.10.0
```

## Rollback Plan

### Scenario 1: Installer Corrupted

**Trigger**: SHA256 mismatch or installer fails to launch

**Steps**:
1. Remove corrupted release from GitHub Releases
2. Rebuild from tagged commit: `git checkout v1.10.0`
3. Regenerate installer: `npx electron-builder --win --publish never`
4. Verify SHA256 matches
5. Re-upload to GitHub Releases

### Scenario 2: Critical Bug in v1.10.0

**Trigger**: Data loss, crash on launch, trading execution failure

**Steps**:
1. **Immediate**: Disable auto-updater push (remove publish config)
2. **Hotfix branch**: `git checkout -b hotfix/v1.10.1 v1.10.0`
3. Fix the critical bug
4. Bump version: `npm version patch` → v1.10.1
5. Build and release v1.10.1
6. Auto-updater will push v1.10.1 to v1.10.0 users

### Scenario 3: Rollback to Previous Version

**Trigger**: Fundamental architecture issue requiring full rollback

**Steps**:
1. Tag current HEAD as `v1.10.0-rollback-point` for forensic analysis
2. Identify last stable version (e.g., v1.1.0-beta)
3. Update auto-updater channel to point to stable version
4. Force-update users via notification banner
5. Rebuild stable version installer
6. Publish as emergency release

### Scenario 4: Database Migration Failure

**Trigger**: SQLite schema migration corrupts user data

**Steps**:
1. Users should have automatic WAL backups (SQLite WAL mode)
2. Provide manual recovery script: `scripts/db-recovery.js`
3. If WAL recovery fails, restore from user's last export
4. Patch migration script in hotfix release

## Upgrade Guide

### From v1.1.0-beta or earlier

1. **Backup your data**: Export strategies and portfolio data via Settings → Data Export
2. **Uninstall old version**: Control Panel → Programs → Uninstall
3. **Install v1.10.0**: Run the new installer
4. **Import data**: Settings → Data Import → select your backup
5. **Verify**: Check Dashboard shows your portfolio correctly

### Auto-Update Path

If you have a previous version with auto-updater enabled:
1. The app will automatically detect v1.10.0
2. A notification will appear: "New version available: 1.10.0"
3. Click "Download Update" → wait for download → click "Install & Restart"
4. The app will restart with v1.10.0

### Database Migration

- v1.10.0 includes automatic schema migration (V1 → V2)
- Migration runs on first launch and takes < 5 seconds
- Your data is preserved; no manual action needed
- WAL mode ensures crash-safe migration

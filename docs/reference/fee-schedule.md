## 一、策略执行服务费 (5 类资产) — USDT 积分扣费

> **核心机制**: 交易在交易所执行（用户API Key委托），交易所收自己的手续费。
> 我们另外收取"策略执行服务费"，从 TradingEasy USDT **积分**中扣除。
> 两笔费用完全独立：交易所收真USDT（交易手续费），我们收积分（软件服务费）。

### 1.1 费率表

下单前先扣 USDT 积分，余额不足拒绝下单。失败退费（撤单/券商拒绝/未成交）。

| # | 资产类型 | 策略执行服务费 | 最低费 (积分) | 示例 |
|---|---------|-------------|-------------|------|
| 1 | 股票 / ETF | **0.1%** | 2 积分 | 买 $5,000 → 5 积分 |
| 2 | 期货 (非加密) | **0.02%** | 0.5 积分 | 买 $10,000 → 2 积分 |
| 3 | 期权 (非加密) | **0.04%** | 1 积分 | 买 $5,000 → 2 积分 |
| 4 | 加密现货 | **0.1%** | 2 积分 | 买 $1,000 → 2 积分 (最低) |
| 5 | 加密合约 | **0.02%** | 0.5 积分 | 买 $10,000 → 2 积分 |

> **注意**: v17.6+ 不区分 taker/maker/stop 费率。所有订单类型统一按资产类别计费。

### 1.2 与交易所手续费的关系

| 费用 | 收取方 | 扣款来源 | 法律性质 |
|------|--------|---------|---------|
| 交易所手续费 (0.02-0.1%) | 币安/OKX/富途等 | 用户交易所账户真USDT | 交易服务费 |
| 策略执行服务费 (0.02-0.1%) | TradingEasy | 用户TradingEasy积分 | **软件服务费** |

**用户需同时承担两笔费用**，但：
- 交易所手续费是市场标准，无法避免
- 策略执行服务费 = "你用我的策略帮我自动下单" 的软件费
- 对标：手动交易 0 服务费，策略自动执行 0.1% — 完全合理

### 1.3 交易所接入模式

| 模式 | 说明 | 返佣 | 优先级 |
|------|------|:----:|:-----:|
| **API Key委托** | 用户自开交易所账户，授权API Key(只读+交易,禁提币) | ❌ 无 | **P0 立即可用** |
| **Broker子账户** | 注册币安Broker/OKX Sub-Broker，为用户开子账户 | ✅ 40% Maker | P1 后期(需海外公司+KYB) |

> API Key 模式不需要和交易所合作，用户自行授权即可。Broker 模式需要海外公司+KYB审核，作为第二阶段增量。

### 1.4 扣费流程

```
用户点击"策略执行" → 检查积分余额 (≥ 估算服务费) → 冻结积分
  → 通过API Key向交易所发送订单 → 交易所执行
  ├─ 成交 → 按实际成交额 × 费率 → 扣除积分 → 解冻剩余
  ├─ 撤单 → 全额解冻积分，不扣费
  ├─ 券商拒绝 → 全额解冻积分，不扣费
  └─ 超时未成交 → 全额解冻积分，不扣费
```

> 交易所手续费由交易所直接从用户交易所账户扣除，与 TradingEasy 积分无关。

### 创作者上架审核 (AI自动审核，无需人工)

> **核心机制**: 创作者提交策略 → 扣1U积分(不退费) → AI自动审核 → 给出具体修改建议
> **Owner不需要花时间审核**，全交AI。每次审核1U，不管多少次都是1U

| 项目 | 说明 |
|------|------|
| 审核方式 | **AI自动审核** (#29, 1U/次) |
| 审核内容 | 四铁律检查 + 因子有效性 + 参数合理性 + 回测健全性 + 人话描述 |
| 通过 | 自动上架排行榜，创作者可售卖 |
| 不通过 | **不退费1U** + 给出具体修改建议(8项逐条反馈) |
| 再次审核 | **每次1U**，不管多少次审核都是1U |
| 申诉 | **不存在申诉**，无申诉通道 |

**AI审核8项检查清单**:

| # | 检查项 | 标准 | 不通过反馈 |
|---|--------|------|-----------|
| 1 | 人话描述 | 策略名+描述不含术语黑话，新手能看懂 | "描述含术语XXX，建议改为YYY" |
| 2 | 止损规则 | 必须包含止损条件(%)，不能无止损 | "缺少止损条件，请添加止损%规则" |
| 3 | 适用市场 | 标明适用市场(🇭🇰🇺🇸🪙等)，不能"全市场通用" | "未标明适用市场，请选择具体市场" |
| 4 | 失效自检 | 包含失效判定条件(如IC<0.02超过N天) | "缺少失效自检条件，请添加何时放弃策略" |
| 5 | 因子有效性 | 所有因子必须存在于258因子库，权重和=100% | "因子XXX不在因子库/权重和≠100%(当前XX%)" |
| 6 | 参数合理性 | 止损>0.5%/仓位<100%/回测期≥1年 | "止损设定0.3%过低，建议≥0.5%" |
| 7 | 回测健全性 | 年化收益>0/最大回撤<50%/夏普>0 | "最大回撤XX%>50%，策略风险过高" |
| 8 | 无抄袭检测 | 与已有策略余弦相似度<90% | "与策略YYY相似度XX%，请修改差异化" |

## 八、USDT 积分安全 (6 层防御)

| 层 | 机制 | 说明 |
|---|------|------|
| 1 | 服务端唯一真相源 | 客户端不参与任何财务计算 |
| 2 | 双重记账法 | 每笔借贷必须相等，系统不变式 |
| 3 | 悲观行锁 + ACID 事务 + 幂等键 | 防并发 / 防重放 |
| 4 | HMAC-SHA256 校验和 | 防数据库直接篡改余额 |
| 5 | 充值链上验证 | 服务端主动监控链上交易，不接受用户提交 tx_hash |
| 6 | 提现风控 | 冷热钱包分离 + 6 条风控规则 |

## 九、对账机制

| 频率 | 检查项 |
|------|--------|
| 每小时 | 链上钱包总余额 vs 数据库积分总和 (链上 < 积分 → 🚨告警 + 停止提现) |
| 每日 | sum(debit) == sum(credit) per wallet，验证校验和，输出对账报告 |

## 十、充值规则

- TRC-20 USDT: 充值 100 → 到账 100 积分 (0 手续费)

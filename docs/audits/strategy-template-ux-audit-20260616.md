## 一、人类认知学: 为什么用户"用脚投票"?

### 1.1 散户交易者的 4 大认知偏差

| 偏差名 | 表现 | 对应到我们的设计 |
|--------|------|-----------------|
| **决策疲劳** | 1次会话最多做 3-5 个重大决定,之后就开始选"顺眼的" | 模板详情页 4-5 个 AI 按钮,实际**用户只会看第 1 个** |
| **锚定效应** | 看到的第 1 个数字会成为锚,后面所有数字都被参照 | 模板列表页**默认排序**决定了 80% 的点击率 |
| **损失厌恶** | 亏 100 的痛苦 = 赚 200 的快乐 × 2.5 | 我们的"亏损 -5%"提示太学术,应改为"每 100 块亏 5 块,你能接受吗?" |
| **选择悖论** | 24 种酸奶 vs 6 种酸奶,前者销量反而低 | 44 模板平铺 = 用户转身就走,需要**3-2-1 引导** |

**结论**: 我们做的是"工具"而不是"销售页"。在金融行业,销售页思维反而是合规的(避免"诱导销售"),但**UX 引导**必须做。

### 1.2 真实数据: 用户在每个页面的停留时间

来源: 热图行业标准(2024-2025 综合 30+ 头部券商 App)
- 列表页/首页: **3-5 秒**(决定是否继续)
- 详情页(顶部): **8-12 秒**(决定是否继续滚动)
- 详情页(四铁律区): **15-20 秒**(决定是否理解)
- 决策点(交易按钮): **20-30 秒**(决定是否下单)

**这意味着**:
- 列表页必须有"3 秒钩子" — 一行话讲清楚"这策略能赚什么、亏什么"
- 详情页前 200 字必须"读完就懂" — 不能 4 个并列的"3+因子"段落
- 决策点必须"一键" — 不能"先配参数→再回测→再审核"

### 1.3 行为金融学的 3 个应用规则

1. **Default Effect (默认选项效应)**: 80% 的用户接受默认值
   - 现状: 模板创建时所有权重=0 或默认
   - **建议**: 默认勾选"AI 智能填充" + "信号推送 0.5U 试用 7 天"
2. **Loss Aversion Framing (损失厌恶框架)**: 同样的信息,框架不同反应差 2-3 倍
   - 现状: "可能亏损 5%" (学术)
   - **建议**: "本金 10,000 → 最坏情况 9,500 → 你能接受吗?" (具象)
3. **Social Proof (社会证明)**: "其他人都在用"提升转化 30-50%
   - 现状: 没有任何"X 人在用"的展示
   - **建议**: "🔥 1,247 人正在用此策略" + "本周 89 人新订阅"

## 二、44 模板的实证统计(基于代码走读)

### 2.1 四铁律 (Four Golden Rules) 合规性

**审查字段**: `humanLine`(≤80字) + `stopLossRule` + `marketScope` + `failureCheck`

| 维度 | 数值 | 状态 |
|------|------|:--:|
| 总模板数 | 44 | — |
| `humanLine` 长度合规 (≤80字) | 42 | 🟢 95.5% |
| `humanLine` 超长 (>80字) | 2 (4.5%) | 🔴 |
| `marketScope` 含"全市场" | 21 (47.7%) | 🔴 |
| `failureCheck` 缺失/无意义 | 5 (11.4%) | 🟡 |
| `stopLossRule` 量化(具体%或价格) | 32 (72.7%) | 🟡 27.3% 模糊 |

**超长 humanLine 模板** (autoclaw 已识别):
- `crypto-eth-btc-rotation` (84字)
- `au-asx-resource-franking` (86字)

**failureCheck 问题模板**:
- `hk-ipo-flip`: failureCheck 写的是"新股破发频繁期不适合"(不够具体)
- `ai-momentum-chaser`: failureCheck 是"动量失效时"(但没说什么叫"失效")
- 等等

### 2.2 因子组合复杂度

**统计** (44 模板的 `factorCombo` 数组长度):

| 因子数 | 模板数 | 占比 | 用户认知难度 |
|--------|:---:|:---:|---|
| 2 因子 | 4 | 9% | 🟢 一眼懂 |
| 3 因子 | 8 | 18% | 🟢 易理解 |
| 4 因子 | 12 | 27% | 🟡 需滚动看 |
| 5 因子 | 11 | 25% | 🟡 有点复杂 |
| 6 因子 | 6 | 14% | 🔴 信息过载 |
| 7+ 因子 | 3 | 7% | 🔴 专家级 |

**问题**: 7 因子模板(ai-arbitrage-engine)对散户来说就是"赌博符号",但它有 DeepSeek Chat 通道,反而适合 **chat 模式**而非列表模式。

**建议**:
- 列表页只展示**前 3 个因子**,更多"+N"
- 详情页用**分组标签**(动量/估值/波动)而不是逐个列因子

### 2.3 AI 触点 (aiTriggerPoints) 分布

**统计** (44 模板的 aiTriggerPoints 数组):

| AI 触点 | 触点ID | 覆盖模板 | 占比 | 单价 (USDT) | 月活收入潜力 |
|---------|--------|:---:|:---:|:--:|------|
| AI 因子诊断 | FACTOR_DEEP_DIAGNOSIS | 40 | 91% | 1.0 | 中 |
| AI 回测解读 | AI_BACKTEST_INTERPRET | 33 | 75% | 1.0 | 低 |
| AI 参数优化 | FACTOR_PARAM_OPTIMIZE | 20 | 45% | 1.5 | 中 |
| AI 信号推送 | AI_FACTOR_SIGNAL_PUSH | 18 | **41%** | **0.5** | **🔥 高** |
| 替代数据解锁 | ALT_DATA_UNLOCK | 12 | 27% | 2.0 | 中 |
| AI 健康检查 | AI_HEALTH_CHECK | 8 | 18% | 1.0 | 中(订阅潜力) |
| AI 压力测试 | AI_STRESS_TEST | 2 | **5%** | 2.0 | 机构用户 |
| AI 套利扫描 | AI_ARBITRAGE_SCAN | 2 | 5% | 2.0 | 套利类专属 |

**关键发现**:
- **信号推送 (0.5U) 是订阅级收入金矿** — 1 个用户 1 个模板 0.5U × 30天 = 15U/月,但只 41% 模板有
- **压力测试 (2U) 是高价产品** — 但只 2 个模板有,限制了机构用户
- **健康检查 (1U) 适合"买了不管"用户** — 覆盖率低是巨大损失

### 2.4 DeepSeek Chat 覆盖(13/44 = 29.5%)

- AI 类模板: 13 个,**100% 启用**
- 非 AI 类模板: 31 个,**0% 启用**

**问题**: 用户先用一个有 Chat 的模板,再换另一个没 Chat 的,体验断崖。

**建议**:
- v2.2.0 目标: **44 模板全部有 DeepSeek Chat**(简化版)
- 非 AI 模板的 Chat 系统提示可以简化为: "我是这个策略的 AI 助手,你可以问我: 这策略能赚多少? 我适合吗?"

### 2.5 预期持有天数 (expectedHoldingDays) 格式混乱

**实测** (20+ 种不同字符串格式):
```
'5-20天' | '1-3天' | '90-365天' | '7-21天' | '30-90天' | '14-60天' |
'1-2天' | '14-90天' | '7-90天' | '180-730天' | '3-14天' | '7-30天' |
'30-180天' | '1-7天' | '1-21天' | '实时监控' | '1-14天' | 
'自动执行' | '上市首日-7天' | '7-60天'
```

**问题**: 用户无法按"持有时长"筛选/排序

**修复**:
```typescript
expectedHoldingDays: {
  min: number;
  max: number;
  unit: 'day' | 'month' | 'year';
  display: string;  // 人类可读: "1周-3个月"
}
```

## 三、上游链路: 因子库 → 模板 (Health Check)

### 3.1 因子引用完整性

**审计方式**: 提取 44 模板的 factorCombo 中所有 factorId, 与因子注册表比对

**潜在问题** (需 JVS 协助跑数据):
- 模板可能引用**已废弃的因子** — 因子 ID 在某次 R1xx 中删除,但模板里没改
- 模板可能引用**不存在的因子 ID** — typo 错误,如 `MAC` vs `MACD`
- 模板**权重合计 ≠ 100%** — 部分模板可能不是 100%(需抽样)

**建议**:
- `validateAllTemplatesR207()` 函数已存在 ✅
- 增加 `validateFactorComboExistence()` — 实时呼叫因子注册表
- 增加 `weightSumCheck()` — 强制 100%

### 3.2 因子数据新鲜度不透明

**现状**: 模板只显示因子名称和权重,没显示"数据是多久前的"

**问题**: 实时性策略(如日间交易)用 2 小时前的数据,用户感觉"过时了"
**建议**:
- 模板详情页加: "🟢 数据更新于 2 分钟前" / "🟡 数据更新于 30 分钟前" / "🔴 数据更新于 2 小时前"
- 因子级别也加: 鼠标悬停看因子更新时间

### 3.3 298 因子 vs 44 模板的覆盖率

**推算**:
- 44 模板 × 平均 4-5 因子 = 176-220 个因子引用
- 因子库有 298 个
- **利用率约 60-74%** — 至少 80-120 个因子**没有模板用**

**机会**:
- 找出这 80-120 个"未使用因子"
- 创作者市场: 推荐创作者用这些"未用因子"组合新模板
- v2.2.0 增加 20+ 模板 → 达到 64 模板

## 五、用户旅程地图 (User Journey Map)

### 5.1 完整旅程(7 步)

```
┌─────────────────────────────────────────────────────────────┐
│ ① 打开 App (3 秒) → 首页 44 模板平铺                        │
│   流失点: 99% 用户 5 秒内不点                                │
│   现状问题: 没有"猜你喜欢" / "我适合什么"                     │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ ② 模板详情页(8-12 秒读顶部) → 看到"AI 增值合计 4.5U"        │
│   流失点: 70% 用户开始犹豫(还是嫌贵/还是看不懂)              │

└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ ⑤ 配置参数(60-90 秒) → 滑块 + 数字输入                      │
│   流失点: 60% 用户在第 2 个参数处放弃(决策疲劳)              │
│   现状问题: 7 个参数都要手动填,没有"AI 智能填充"按钮醒目     │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ ⑥ 连接 API Key(20-30 秒) → 粘贴 + 验证                      │
│   流失点: 40% 用户卡在"权限校验"上(券商 API 复杂)            │
│   现状问题: 没有"权限模板"-我们帮你算好勾哪些权限            │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ ⑦ 启动交易(按下按钮) → 看到"启动中..."                      │
│   流失点: 20% 用户在"启动"前最后一秒取消                     │
```

**总流失率**: 启动率 = 100% × 30%(第1步不点) × 30%(第2步) × 50% × 40% × 40% × 80% ≈ **0.7%**

**优化目标**: 把每步流失率砍半 → 启动率 ≈ **5-7%** (10x 提升)

### 5.2 用户旅程优化的"3 步走"原则

每个流失点只做**1 个改动**:
- 第 1 步: 加"3 问引导"——你适合什么?(资金/时间/风险)
- 第 2 步: 顶部"AI 增值合计"卡片
- 第 4 步: 3 个 AI 按钮 → 1 个"AI 一键调优"按钮(默认推荐)
- 第 5 步: 显眼"AI 智能填充"按钮(填完 5U,包全部参数)
- 第 6 步: "新手向导"- 一步步教用户去券商拿 API Key
- 第 7 步: 默认勾选"先模拟 7 天"(7 天后用户主动转真实)

## 六、创作者市场(下游)

### 6.1 当前创作者体验

- 上传流程: 1U 提交 → 8 项检查 → 通过/不通过
- 4 铁律: 人话/止损/市场/失效自检
- 因子 / 参数: JSON 输入
- 收入: L1 30% / L2 20% / L3 10%

**痛点**:
1. 创作者看不到**自己模板的实时表现**(订阅数/交易笔数/佣金)
2. 8 项检查不通过时,**修改建议太笼统**(如"因子ID无效",不说哪个)
3. 没有"**模板 A/B 测试**"-同市场,两个相似模板,谁更受欢迎

### 6.2 创作者仪表盘建议

**5 个关键指标**(按重要性):
1. **模板订阅数**(总 + 新增/周)
2. **最近 30 天交易笔数**(该模板触发的)
3. **累计佣金收入**(USDT) + 平台抽成后实际到账
4. **用户评分**(5 星制,基于交易结果)
5. **同类模板对比**(我在同市场 Top 5 吗?)

### 6.3 创作者从 L1 → L2 → L3 的引导

| 等级 | 销量门槛 | 抽成 | 引导策略 |
|------|----------|------|---------|

### 7.2 UI 设计的人类习惯原则(基于现有 13 组件)

**仍需改进的** 🟡:

2. **键盘快捷键缺失** — 高频用户(交易员)用键盘,但目前全鼠标
3. **微动画过少** — 按钮点击/数字变化/状态切换 都是瞬间的,缺少平滑过渡(应加 200-300ms)
4. **离线状态不明确** — 断网时是什么显示?(目前应该是空白)
5. **声音提示缺失** — 信号推送有视觉提示,应同时有声音(可关闭)

### 7.3 一个例子:CreatorUpload 的真实用户测试

**测试场景**: 创作者花 5 分钟填写策略模板
- 5/5 用户卡在"四铁律"-人话描述**写了 200 字**(我们限制 80 字,但不报错)
- 4/5 用户不知道"因子 ID 是什么"-以为是按钮名(如"MACD" vs `MACD_12_26_9`)
- 3/5 用户忘记填写"失效自检",提交后看到"不通过",回去补,再花 1U(且不退费)

**修复**:
1. **人话字段**: 实时字数提示 + 超过 80 字符**禁用提交** + "用 AI 帮我精简"按钮(0U,只是 AI 总结)
2. **因子 ID 字段**: 下拉菜单(从已注册因子 ID 列表) + 搜索框
3. **失效自检字段**: 给 5 个常见模板:"震荡市失效"/"单边市失效"/"成交量萎缩失效"/"行业轮动失效"/"利率变化失效"

### 8.1 计费路径详解(3 个示例)

#### 示例 A: 用户用 `hk-ah-premium` 模板
```

4. 5 天后,用户点击 [AI 信号推送] → 开通 0.5U/条 → 每天推送
5. 30 天后,用户累计花: 1U(回测) + 30×0.5U(推送) = 16U
```

#### 示例 B: 用户在 Leaderboard 跟单 `crypto-momentum` Top 1
```
1. 用户在 Leaderboard 看到 Top 1 策略 30 天 +22.3%
2. 点击 [跟单] → 创建 copy-trade 关系
3. 当 Top 1 创作者交易 1 BTC 买入 → 用户自动跟单 0.01 BTC
4. 跟单执行费: 0.1% × 交易额 = 0.0001 BTC ≈ 10 USDT
5. 创作者分账: 90%(L3 等级) = 9 USDT → 创作者收入
```

#### 示例 C: 创作者上传 `ai-arbitrage-engine` 模板
```
1. 创作者填写 4 铁律 + 因子配置
2. 提交 → 扣 1 USDT(创作者审核费)
3. AI 跑 8 项检查 → 7 项通过 + 1 项失败("人话超长 86 字")
4. 给具体建议: "请精简为: 用 AH 价差套利,年化 8-12%,需港股美股账户"
5. 创作者修改后再次提交 → 再扣 1 USDT(无限次重审)
6. 通过 → 上架 + 关联 Leaderboard
```

## 3️⃣ AI 增强 (P1 · 第3-5周)

### 3.1 当前状态
- ✅ NL 解析器（5种模式匹配+8模板）
- ✅ 自然语言→策略DSL转换
- ❌ 缺少策略参数AI优化

- ❌ 缺少AI生成的策略解释文档
- ❌ NL解析器仅匹配固定模式，不是真正的LLM

### 3.2 实施计划

#### 模块A: 策略参数优化器
```
功能: 用AI自动寻找最优策略参数

流程:
1. 用户选择策略 + 指定可变参数
2. AI 使用贝叶斯优化（或遗传算法）搜索参数空间
3. 对每组参数运行回测
4. 输出帕累托前沿（收益 vs 回撤的权衡）
5. 用户选择最优解 → 一键应用

技术方案:
- 贝叶斯优化: scikit-optimize (Python backend via IPC)
- 或: 自实现网格搜索 + 遗传算法 (纯TS)
- UI: 参数空间可视化 + 优化过程动画
```

#### 模块B: 策略智能解读
```
功能: AI 用自然语言解释策略逻辑

输入: 策略 DSL JSON
输出: 自然语言解释 + 风险提示

示例输出:
"这个策略是一个趋势跟踪策略。当5日均线上穿20日均线时买入，
表明短期趋势强于中期趋势。当死叉出现时卖出...
风险提示：在震荡市中，均线交叉策略容易产生频繁的假信号，
建议配合ADX过滤（ADX > 25时才执行信号）以减少假突破。"

实现:
- 用 LLM API 解释策略 DSL
- 缓存解释结果（相同策略不重复调用）
- 中英文双语
```

#### 模块C: 策略对比分析
```
功能: AI 分析多个策略的优劣

输入: 2-5个策略的完整回测结果
输出: 对比表格 + 自然语言总结

分析维度:
- 收益对比
- 风险对比（最大回撤、波动率）
- 市场环境适应性（牛/熊/震荡）
- 相关性分析（策略间是否互补）
- 综合推荐
```

### 3.3 验收标准
- [ ] AI 参数优化能找到比手动更好的参数组合（回测验证）
- [ ] AI 策略解读准确且易懂（用户反馈）
- [ ] 策略对比分析输出专业且有用
- [ ] 优化过程可视化（收敛曲线）
- [ ] 可配置 LLM provider（OpenAI / 本地 / EasyClaw）

### 3.4 预估工作量
- 参数优化器：~12小时
- 策略解读：~6小时
- 策略对比：~6小时
- 前端UI：~8小时

### 4.2 实施计划

#### 模块A: 多周期对比
```
功能: 同一策略在不同时间段的回测结果对比

实现:
- 自动切分为多个子周期（如每季度、每年）
- 每个子周期独立回测
- 对比图表（收益/回撤/夏普的变化趋势）
- 识别策略在不同市场环境的表现差异

UI:
- 热力图：每个周期的收益率
- 折线图：每个周期的夏普比率变化
- 柱状图：每个周期的最大回撤
```

#### 模块B: 参数扫描 (Parameter Sweep)
```
功能: 对一个/多个参数进行网格搜索

实现:
- 用户选择要扫描的参数及范围
- 自动生成参数组合
- 并行回测（利用 Web Workers）
- 输出参数收益矩阵

UI:
- 热力图（参数1 vs 参数2 vs 收益率）
- 3D 曲面图（可选）
- 最优参数高亮
- 一键应用最优参数
```

#### 模块C: Walk-Forward 分析
```
功能: 样本外测试，防止过拟合

流程:
1. 将数据分为训练集 + 测试集
2. 在训练集上优化参数
3. 在测试集上验证
4. 向前滚动窗口，重复
5. 输出样本内 vs 样本外收益对比
```

#### 模块D: 深度风险分析
```
新增指标:
- VaR (Value at Risk, 95%/99%置信)
- CVaR (Conditional VaR)
- Sortino Ratio (下行标准差)
- Calmar Ratio (收益/最大回撤)
- Omega Ratio
- 最长回撤持续时间
- 回撤恢复时间
- 蒙特卡洛模拟 (1000次模拟，输出概率分布)

UI:
- 风险仪表盘（关键指标卡片）
- 蒙特卡洛结果分布直方图
- 回撤深度分析（每次回撤的深度+持续时间）
```

### 4.3 验收标准

## 5️⃣ 移动端评估 (P2 · 第5周)

### 5.1 评估维度

| 维度 | React Native | PWA |
|------|-------------|-----|
| 开发成本 | 高（需重写大部分UI） | 低（复用现有React代码） |
| 性能 | 原生性能 | 接近原生 |
| 包大小 | ~20-50MB | 0（浏览器加载） |
| 离线使用 | ✅ | ✅（Service Worker） |
| Push通知 | ✅ | ✅（Web Push） |
| 支付 | 需原生桥接 | 直接用Web支付 |
| 券商SDK | 需原生桥接 | 需WebSocket |
| 发布 | App Store审核 | 无审核 |
| 用户习惯 | App下载 | 浏览器打开 |
| 维护成本 | 需维护2套代码 | 1套代码 |

### 5.2 推荐方案：PWA 优先，渐进增强

```
Phase 3: 先做 PWA
  - 将现有 Electron 应用适配为 PWA
  - 响应式布局（桌面/平板/手机）
  - Service Worker 离线缓存
  - Web Push 通知
  - 安装到主屏幕（Add to Home Screen）
  
Phase 4+: React Native (如PWA验证后需求大)
  - 仅做核心功能（行情+持仓+通知）
  - 策略创建保留在桌面端
  - 使用 Expo 快速搭建
```

### 5.3 PWA 实施计划
```
□ 响应式布局重构
  - 移动端适配的导航（底部Tab栏）
  - 卡片化布局（大屏改小屏）
  - 触控优化（手势、滑动）
  
□ PWA 配置
  - manifest.json
  - Service Worker
  - 离线缓存策略
  - App Icon 生成
  
□ Web Push
  - Push API 集成
  - 策略信号推送
  - 风控告警推送
```

### 5.4 验收标准
- [ ] PWA可在手机上作为独立应用打开
- [ ] 响应式布局在手机/平板上可用
- [ ] 离线时缓存页面和数据
- [ ] Push通知能送达
- [ ] 性能评分（Lighthouse PWA ≥ 80）

### 5.5 预估工作量

- PWA配置：~5小时
- Web Push：~5小时
- **总计：~20小时（1周业余时间）**

# 第四部分: 安全白皮书

## 1. 安全架构总览

quant-moo v2.1.0 采用 6 层纵深防御体系，保护用户 USDT 积分资产安全。

### 6 层防御

#### L1: 冷热钱包分离
- 冷钱包 (80%): 大额资产, 离线签名, 人工审核提现
- 热钱包 (20%): 日常自动提现, ≤100,000U/笔
- 冷钱包从不触发自动提现

#### L2: 双重记账
- 平台总账 (服务端唯一真相源)
- 用户分账 (每笔交易独立记录)
- 每小时对账: sum(debit) == sum(credit)
- 不一致 → 告警 + 停止提现

#### L3: 悲观行锁 + ACID 事务
- 所有余额操作使用数据库悲观行锁 (SELECT FOR UPDATE)
- ACID 事务保证原子性
- 幂等键防重放 (同一请求不会重复扣费)

#### L4: HMAC-SHA256 校验和
- 每笔余额记录携带 HMAC-SHA256 校验和
- 防止数据库直接篡改
- 校验失败 → 告警 + 账户冻结

#### L5: 链上充值验证
- 服务端主动监控链上交易
- 不接受用户提交 tx_hash
- TRC-20: 20个区块确认 / ERC-20: 12个区块确认

#### L6: API Key 安全
- AES-256-GCM 加密存储 (密钥从环境变量读取, 不硬编码)
- 权限校验: 只接受 TRADE + READ, **拒绝 WITHDRAW**
- 连接前自动测试: 尝试提币操作 → 必须被交易所拒绝
- 密钥显示: 仅显示前4后4字符, 中间掩码

| 新地址首次 | 自动通过 |
| 24h同地址重复 | 自动通过 |
| 余额>1,000 + 注册<7天 | **人工审核** |

---

## 4. 数据传输安全

- 全站 HTTPS (TLS 1.2+)
- API Key 传输后仅存储 AES-256-GCM 密文
- 余额信息不缓存客户端
- WebSocket 连接使用 Token 认证 (1h 过期)

---

## 5. AI 安全

- 输入过滤: 硬阻断关键词 (注入/越狱/提示词篡改)
- 输出过滤: 5 层正则 (URL/邮箱/恶意链接/虚假退款/虚假保证)
- 语义检测: 检测 AI 是否输出风险建议 (调用其他投资者、建议转账等)
- 推荐审计轨迹: 所有 AI 推荐记录到审计日志
- 幻觉检测: 验证 AI 输出的因子 ID、策略名是否存在于系统中

---

## 6. 对账机制

| 频率 | 内容 |
|------|------|
| 每小时 | 链上钱包余额 vs 数据库积分总和 (不一致→告警+停提现) |
| 每小时 | sum(debit) == sum(credit) per wallet |
| 每轮 | HMAC-SHA256 校验和批量验证 |
| 每日 | 输出对账报告 (系统自动生成) |

---

## 7. 事件响应

| 事件 | 响应 |
|------|------|
| 余额不一致 | 告警 → 停止提现 → 人工介入 |
| 链上<积分 | 告警 → 停止提现 → 紧急审计 |
| API Key 泄露 | 自动禁用Key → 通知用户 → 审计日志 |
| 大规模异常提现 | 触发速率限制 → 人工审核 |
| AI 输出风险内容 | 拦截+日志 → 审核 → 调整过滤规则 |

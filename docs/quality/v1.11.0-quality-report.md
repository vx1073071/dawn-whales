## Appendix A: Methodology

### Data Collection Methods
Each metric in this report was collected using repeatable, verifiable commands:

- **TSC errors**: `npx tsc --noEmit` — run from project root, counts TypeScript compilation errors
- **Build errors**: `npm run build` exit code (0 = success)
- **i18n CJK chars**: `grep -rP '[\u4e00-\u9fff\u3040-\u30ff]' src/ electron/ | wc -c` — counts CJK Unicode characters in source
- **EngineError%**: `grep -r 'new EngineError' electron/engine | wc -l` / `grep -r 'throw new' electron/engine | wc -l`
- **Coverage**: `vitest run --coverage --coverage.reporter=json-summary` → `coverage/coverage-summary.json`
- **npm audit**: `npm audit --omit=dev` — production dependencies only
- **Unit tests**: `vitest run` — 5-round average for flaky detection
- **E2E tests**: `npx playwright test --project=chromium` — output parsed for pass/fail counts
- **Bundle size**: `ls -la dist/assets/index-*.js` — main entry point JS file size
- **Storybook**: Component count from `src/stories/*.stories.tsx` file count
- **Git metrics**: `git log --oneline | wc -l` for commit count, `git diff --stat` for file changes

### Verification Protocol
Every round's metrics were independently verified through:
1. youdao runs `vitest run` + `playwright test`

## Appendix C: Lessons Learned (13 Rounds)

### 1. Automated Refactoring Without Review Is Catastrophic
The R92 `if (!result) { return; }` injection across 65+ test files and the `\1\2` i18n corruption in 15 engine files both came from automated regex replacements. **Lesson**: Always run full test suite after any automated code modification.

### 2. i18n Migration Must Use AST, Not Regex
The i18n tool corrupted source files by injecting `i18n.t()` calls mid-string and mid-import. **Lesson**: i18n migration tools must validate against TypeScript AST.

### 3. Coverage Improvement Is Non-Linear
35→55% required ~200 tests. 55→65% would require ~400 more. **Lesson**: Coverage targets should account for the test-writer effort curve.

### 4. 5-Round CI Is the Gold Standard
Running the full suite 5 consecutive times immediately exposes flaky tests. **Lesson**: Multi-round testing should be standard for quality gates.

### 5. Cross-Shrimp File Conflicts Are Inevitable
JVS, QClaw, and youdao all added test files during R95, causing duplicate names and regression failures. **Lesson**: Establish file naming conventions and ownership boundaries early.

### 6. Static Build E2E Has Inherent Limitations
Electron APIs cause JS errors in browser-only E2E tests. **Lesson**: Filter expected errors or mock Electron APIs for E2E.

### 7. Internationalization Is a Multi-Layer Problem
Timezone (R98), number/currency (R99), and language (R100) required three separate rounds. **Lesson**: Break i18n into independent modules with clear interfaces.

### 8. Test-While-Building Works
Writing tests against expected APIs (R98-R99) allowed parallel work with ML/JVS. **Lesson**: Define API contracts upfront, write tests first.

### 9. Coverage Tools Are Fragile on Windows
Vitest coverage reporter occasionally fails with ENOENT on `.tmp` directories. **Lesson**: Pre-create `.tmp` directory, use `json-summary` reporter.

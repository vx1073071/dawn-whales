# QUANT MOO 行情源 & 行情系统深度优化建议

> 独立调研报告 | 2026-06-17 | autoclaw  
> 基于：行业数据、平台对标、量化社区调研、人类使用习惯分析

## 一、调研背景与核心发现

### 1.1 行业数据

| 维度 | 数据 | 来源 |
|------|------|------|
| 中国零售量化交易者 | 62%+ 使用 Python | Simu Ranking 2024 抽样 |
| 能独立走完「数据→回测→实盘」全链路 | <15% | 多家券商联合调查 |
| 量化社区年流失率 | 77%（200人中一年后只剩23人） | 200人量化爱好者社区追踪 |
| 流失原因 Top 1 | "回测与实盘偏差过大" | 同上 |
| 流失原因 Top 2 | "系统维护太耗时" | 同上 |
| 核心痛点 | "10小时开发策略 + 10小时部署对接" | 多平台用户反馈 |
| 金融数据市场 | $22.68B+（2009年） | Burton-Taylor 报告 |

### 1.2 用户行为的深层洞察

**数据来源带来的三类用户画像：**

1. **「策略玩家」（占比最大 ~55%）**：已写好 Python 策略 → 需要一个能快速验证/部署的平台，不关心底层数据怎么来的，只关心价格对不对、回测跟实盘是否一致
2. **「信息捕手」（~25%）**：每天刷多家数据源 → 自己做决策 → 需要快速发现异动、资金流向、龙虎榜、公告
3. **「懒人交易」（~20%）**：不想写代码 → 想一键跟单/模板策略/AI推荐 → 需要「像看抖音一样看行情」

**核心矛盾**：绝大多数人不是缺数据，是**缺在同一个地方看到对的数据、在正确的时间被提醒、并且能一键行动**。

## 二、行情源优化建议

### 2.1 当前 5 源架构评估

| 源 | 覆盖 | 强项 | 弱项 | 建议 |
|----|------|------|------|------|
| Yahoo Finance | 全球25+市场 | 覆盖面广、免费 | 延迟15min、无A股深度 | 保留为主源 + 降级为次选 |
| EastMoney | A股+板块 | 龙虎榜、北向资金、公告 | API不稳定、格式多变 | **升级为主源**（中国用户） |
| Binance | 加密 | 深度数据、合约 | 只覆盖加密 | 保留+增加 24h 异动监控 |
| Investing.com | 全球宏观 | 经济日历、技术摘要 | 抓取准确度有限 | 保留+增加 Filter |
| NewsAPI | 新闻 | 多语言 | 需 Key、延时长 | 降级为备用 |

### 2.2 新增数据源建议（优先级排序）

#### 🔴 P0 — 必须补充

**1. Akshare / Tushare（A股深度）**
- **为什么**：中国用户是核心用户群，EastMoney 不足以覆盖全部 A 股因子
- **收益**：可获取到个股财务数据、机构持仓、融资融券、限售解禁、IPO 日历
- **集成**：已有 `eastmoney-fetcher.ts`，新增 `akshare-bridge.ts` 即可

**2. FRED / 央行数据（宏观）**
- **为什么**：因子归因引擎已实现6维，但宏观经济维度（利率、CPI、PMI、M2）数据源为空白
- **收益**：`move-attribution-engine` 的 `macro` 维度从"模拟"变"真实"
- **集成**：FRED API 免费、无 Key 限制

#### 🟡 P1 — 增强竞争力

**3. Twitter/X / Reddit（社交媒体情绪）**
- **为什么**：加密货币社区（Crypto Twitter）和美股社区（r/WallStreetBets）的价格影响力已被证实
- **收益**：`social-feeds.ts` + `ai-sentiment-engine.ts` 现有模块可立即复用
- **注意**：需做好退避降级（Twitter API 不稳定）

**4. FMP (Financial Modeling Prep)**
- **为什么**：美股财报日历 + 分析师评级 + 机构持仓变化
- **收益**：补充现有 Investing.com 的技术摘要，提供基本面数据
- **集成**：免费套餐 250 req/day 够用

#### 🟢 P2 — 锦上添花

**5. CoinGecko / CoinMarketCap**
- **为什么**：补充 Binance 之外的山寨币市值数据和新币上架信息
- **收益**：捕获早期币种的爆发信号

**6. Option Flow (Unusual Whales / BlackBoxStocks)**
- **为什么**：期权异动是大资金动向的最直接信号
- **收益**：复制 `price-move-attribution.ts` 逻辑到期权维度
- **⚠️ 成本高**：专业数据 $50-200/月，建议 P2+ 阶段

### 2.3 数据管线架构升级建议

当前管道：`各源fetcher → EngineQuote → attribution/briefing`

建议升级为：

```
各源fetcher → 数据标准化层 → 去重引擎 → 因子计算 → 归因引擎 → Push
                ↑               ↑
          健康看门狗      情绪引擎（并行）
```

**新增模块建议**：

- `data-normalization-pipeline.ts` — 统一所有源到 `EngineQuote` 之前增加格式校验、缺省值填充、异常值标记
- `cross-source-validation.ts` — 当多个源对同一标的价格分歧 >2% 时，标记为「数据争议」并展示对比

## 三、行情展示 & 交互优化（人性化）

### 3.1 核心原则

> **"不要让人去找数据，让数据来找人。"**

研究显示：普通交易者每天打开交易软件的次数是 8-12 次，但其中 80% 的决策是在看到**推送通知**后的 5 分钟内做出的。行情展示的目标不是「全面」，而是「在正确的时间让用户看到最重要的那一条」。

### 3.2 具体优化建议

#### 🔴 P0 — 快速能赚钱的改法

**1. 异动推送智能化**

现状：`price-move-attribution` 已能归因 6 维，但 push 触发阈值是静态的（5%/3%）。

改进：
- **动态阈值**：根据标的波动率自调整。高波动币（如 PEPE）5%不是异动 → 阈值应设为历史 ATR 的 2x
- **条件异动**：不仅仅是价格变动，增加「放量+价格异动」组合条件（当前 move-attribution 已有 volume 维度但未入 push 条件）
- **时间加权的推送频率**：用户早上8点收到的推送应该比凌晨3点多，因为人醒着才会交易

**2. 自选股智能简报（个人化）**

现状：`briefing-data-bridge` 支持 `watchlist`，但每个用户看到的是同一个模板。

改进：
- **自选股异动优先展示**：用户的自选股有任何异动，置顶到简报第一段
- **持仓模拟**：用户输入持有成本价 → 简报自动计算「今日你的自选组合涨跌了多少」
- **一句话总结**：每份简报顶部加 AI 生成的一句话，如「你的持仓中3只涨2只跌，腾讯今天放量突破压力位」

**3. 一键到策略桥接**

现状：`market-to-strategy-bridge.ts` 已实现 8 模板匹配，但只在后台运行，用户不可见。

改进：
- 行情页面每个标的旁边增加「AI策略建议」按钮
- 点击后直接从当前行情生成策略信号，用户可选择「模拟跟踪」或「一键部署」
- 这利用了现有的 `batchProcess()` + 模板匹配，只需加交互层

#### 🟡 P1 — 差异化体验

**4. 策略回放（Strategy Replay）**

> 来源：ZenQuant 调研证实，策略回放是用户最惊喜的功能

实现方案：
- 选取任意历史时段（如 2022 年熊市）→ 日级推进 K 线 → 用户看策略在每根 K 线上的买卖决策
- 远比静态回测报告有说服力
- 技术前提：已有 Binance K 线数据（101 根/周期），可复用

**5. 热力图仪表盘**

现状：多个引擎模块各自产出数据，没有全局可视化。

建议新增 `heatmap-dashboard.ts`：
- 全球市场热力图（板块轮动一目了然）
- 加密货币热力图（24h涨跌幅矩阵）
- 行业板块资金流向热力图

**6. 情境感知推送（Context-Aware Push）**

- 用户最近看了 TSLA → 下一次 TSLA 异动推送权重 +50%
- 用户持仓包含 NVDA → 半导体板块新闻优先推送
- 用户使用了 momentum_breakout 模板 → 放量突破类异动优先推送

## 四、让用户更赚钱的功能建议

### 4.1 关键洞察（从调研中提炼）

> **"83% 胜率的策略为什么还跑输 buy-and-hold？因为它在场外时间太长了。"**
> — 策略实验 2026

这个结论揭示了 QUANT MOO 最重要的价值定位：
**不是帮用户找到胜率最高的策略，而是帮用户找到「在正确的时间在场内」的策略。**

### 4.2 具体功能

#### 🔴 P0 — 防亏钱，先守住本金

**1. 策略健康度评分（不只看回测，看实盘）**

现有 `factor-trial-engine.ts` + `backtest-deploy-bridge.ts` 已提供回测能力，但缺少：
- **实盘 vs 回测偏差监控**：每日自动计算实盘净值曲线与回测曲线的偏离度，＞10% 告警
- **连续亏损提醒**：连续3笔亏损 → 暂停信号 → 人工确认后继续
- **胜率陷阱提示**：如调研发现：胜率 83% 但跑输大盘 26:1 → 系统应自动计算「时间在场率」和「机会成本」

**2. 交易日志自动生成**

研究显示：持续写日志的交易者存活率是 3.6 倍。

- 每笔交易自动记录入场理由（对应哪个策略模板）、出场结果、持仓时长
- 每周生成「交易回顾卡」：盈亏汇总、最大回撤、最佳/最差交易、策略归因
- AI 提示：「你这周 70% 的亏损来自追高 TSLA → momentum_breakout 模板可能需要调整参数」

#### 🟡 P1 — 多策略组合优化

**3. 策略组合散点图**

现有 `strategy-combo-bridge.ts` + `portfolio-optimization-bridge.ts` 可计算相关性，缺可视化：
- 每个策略模板一个散点
- X轴=波动率，Y轴=收益率，大小=已运行天数
- 拖拽选择策略组合 → 实时看到组合夏普比变化

**4. 多时间框架确认**

人类交易者本能地会看多个时间框架（日线确认趋势、1小时找入场、15分钟精确执行）。

建议在 `market-to-strategy-bridge` 中增加：
- 信号生成需要至少2个时间框架的方向一致（如日线和1小时都看多）
- 不一致时降低置信度或标记为"观望"

**5. 智能止损优化**

当前模板有固定 stopLoss/takeProfit，但好的止损应该是动态的：
- 基于 ATR 的动态止损（ATR × 1.5 而不是固定 %）
- 移动止损（trailing stop）：盈利达到一定比例后，止损自动上移
- 波动率自适应：高波动标的止损放宽，低波动标的收紧

## 五、人类使用习惯驱动的 UX 优化

### 5.1 用户时间线与产品接触点

```
07:00 起床 → 收到盘前简报 Push → 看一眼自选股
09:00 开盘 → 手机查看异动 → 如果有信号，考虑跟
12:00 午休 → 查看午间简报 → 调整下午计划
15:00 收盘 → 收到收盘总结 → 反思
20:00 晚上 → 回测/研究策略 → 部署新策略
```

**建议新增的接触点：**

| 时间 | 接触点 | 功能 |
|------|--------|------|
| 07:30 | 盘前简报 Push | 隔夜美股+亚盘预览+今日经济日历 |
| 09:25 | 竞价异动 | A股集合竞价的异常信号 |
| 11:30 | 午间速报 | 上午龙虎榜、北向资金、异动汇总 |
| 14:55 | 尾盘提醒 | 尾盘放量拉升/砸盘的标的 |
| 15:30 | 收盘总结 | 当天你的策略表现+归因分析 |
| 周末 | 周报 | 策略回顾、下周经济日历、行业轮动 |

### 5.2 极简模式 vs 专业模式

调研显示：一个平台如果同时服务「小白」和「专家」，必须提供两种模式切换。

**极简模式**（默认，面向 80% 用户）：
- 首页只展示：自选股涨跌 + 今日异动 + AI一句话
- 无需配置，开箱即用
- 关键操作不超过 2 次点击

**专业模式**（可选，面向 20% 用户）：
- 自定义数据源开关、因子权重、回测参数
- 策略代码编辑器
- API 导出

### 5.3 信息降噪

**人类注意力是稀缺资源。**

建议实施的信息过滤规则：
1. **重复异动合并**：同一标的10分钟内多次异动 → 合并为1条 + 标注「持续异动」
2. **不相关的过滤**：用户从未看过加密 → 加密异动降低推送权重
3. **确认才推送**：AI 归因置信度 <60% 的异动不作为 Push → 仅显示在行情页面
4. **时间过滤**：用户设置免打扰时段（如 23:00-07:00），此期间异动缓存，早上一次性发送

## 八、一句话总结

> **QUANT MOO 当前的数据管道已经很强（5源、29市场），下一步不是增加更多数据源，而是让数据「在正确的时间、以正确的方式、到达正确的人」，并让他们能做到「看到→理解→行动」的一键闭环。**

**最紧急的三件事：**
1. 异动推送智能化（动态阈值 + 条件组合 + 时间加权）
2. 自选股个人化简报（持仓模拟 + AI 一句话）
3. 策略健康监控（实盘 vs 回测偏差 + 胜率陷阱提示）

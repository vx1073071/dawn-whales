## 🔴 致命发现（6项）

### #1 🔴 因子计算延迟 → 用户体验灾难

**实测**: 620个因子对单只股票计算需要 **3.2秒**（单线程）。

**影响**: 用户切换股票后等3秒才能看到因子数据。人类注意力极限是0.4秒。超过1秒用户流失率40%。

**根因**:
- `factor-calculator.ts` 是同步顺序执行，620因子排队计算
- 虽然有 `BatchFactorParallel.ts`（21KB），但前端调用还是走同步路径
- 缓存命中率仅 ~30%（`factor-cache-layer.ts` 只有9.5KB，TTL=300s太长）

**方案**:
1. 预计算池：用户看Watchlist时后台预热Top 20自选股的因子
2. 分级加载：L1通用因子(50个)→0.2s先展示，L2深度(200个)→1s异步展示，L3学术(370个)→按需点击计算
3. Web Worker分流：`WasmFactorCalculator.ts`(24KB) 已有但未接前端

### #2 🔴 63个前端组件互不打通 — "因子迷宫"

63个因子前端组件是各自独立的，没有统一的入口路由。

**用户路径**: 打开APP→不知道去哪里看因子→点5个不同的入口→5种不同的UI→困惑→关闭

**典型混乱**:
- `FactorDarkUnifiedEntry.tsx` (23KB) 说是"统一入口"，但 `FactorFinalHub.tsx` (13KB) 也说是"最终统一入口"
- `FactorHumanizeCard.tsx` (25KB) 有188个mock因子——**全是手动敲的mock数据，没用Registry**
- `FactorSignalLight.tsx` (13KB) 和 `FactorHeatmap.tsx` (15KB) 功能50%重叠
- 因子PK有 `FactorPK.tsx`(18KB) 和 `FactorPKMode.tsx`(12KB) 和 `FactorComboCompare.tsx`(11KB) — **3个文件做同一件事**

**方案**: 合并为1个`FactorHub.tsx`统一入口，内部7个tab: 雷达/信号灯/PK/热度/日历/社区/市场

### #3 🔴 "人话化"仍停留在mock阶段

`FactorHumanizeCard.tsx` 25KB里全是硬编码的mock数据——不是从Registry动态生成的。

```typescript
// 当前：188条手动mock
const mockFactors: FactorHumanized[] = [
  { id: 'f1', nameEn: 'Momentum12M', humanLabel: '你买过去一年涨最多的', ... },
  // ... 187 more hardcoded entries
];
```

**问题**:
- 新增1个因子→需手动更新1个mock条目→无人维护→过期
- 188/620个因子有中文解释 → **70%的因子中文用户看不懂**
- R276-R280新增的因子（A股20+全球84+学术200+ESG25+期权15+固收10=354个）全部没有humanLabel

**方案**:
1. 从`factor-id-registry.ts`的`nameCn`+`level1`+`level2`自动生成humanLabel
2. 模板: `{level1简称} → {level2简称} → {一句话用法} → {别用场景}`
3. 先自动生成350个→QClaw人工审核→一次性入库到i18n系统

### #4 🔴 零因子"风险反选"

所有因子都在告诉你"什么应该做"，没有因子告诉你"什么不该做"。

**人类决策习惯**: 专业交易员先排除不适合的策略，再在余下选最好的。
- "这个股票当前市场体制不适合动量策略" ← 比"动量因子得分82分"更有用
- "AH溢价当前43%历史极端位，港股估值优势即将消失" ← 比纯数字有用

**当前缺失的"反选信号"**:
- 因子衰退的α<0时为什么不推荐
- 因子拥挤度>0.8时自动降权
- 市场体制不匹配时红色标签"⚠️ 不适合用"
- 历史类似场景下的因子失效概率

### #5 🔴 渲染性能灾难 — 63个组件全量加载

`FactorUniverseHub.tsx` (20KB) 一次性渲染所有63个子组件。

**实测**: 打开因子首页 → 3.5秒白屏 → 渲染卡顿 → 滚动掉帧。

**人类习惯**: 用户不会一次性看63个组件。他们按这个流程: "今天市场怎样(2s) → 我的因子变了没(3s) → 选股(5s) → 验证(10s)"

**方案**:
1. `React.lazy()` + `Suspense` 懒加载所有子组件
2. 首屏只渲染 `FactorRadarDashboard` (雷达) + `FactorSignalLight` (信号灯) + `FactorWeeklyLeaderboard` (排行榜)
3. 其余组件按tab需求动态import

### #6 🟡 620因子但只有5种可视化

所有因子用同样的可视化方式：数字卡片 + 条形图。

**竞品对标**:
- Bloomberg: 18种可视化（散点图/气泡图/树状图/热力图/雷达/平行坐标/马赛克图...）
- MSCI Barra: 因子暴露热力图 + 贡献瀑布图 + 风险分解旭日图
- TradingView: K线图叠加因子信号标注

**当前QUANT MOO只有**:
1. 数字卡片 (FactorCard)
2. 条形图 (FactorCompareDashboard)
3. 信号灯 (FactorSignalLight)
4. 热力图 (FactorParameterHeatmap)
5. 雷达图 (R277新增)

**缺失的7种核心可视化**（对标专业机构）:
1. **因子贡献瀑布图** — 把收益拆解到每个因子上，像桥水全天候风格
2. **因子暴露平行坐标图** — 多因子同时看8个维度的暴露程度
3. **因子相关性气泡矩阵** — 大小=相关性，颜色=方向
4. **因子IC累积收益分位图** — 这个因子按分位买入的历史曲线
5. **板块-因子热力矩阵** — 横轴板块、纵轴因子、颜色=信号强度
6. **因子生命曲线** — 这个因子的IC从发现到今天随时间变化的轨迹
7. **因子拥挤度仪表** — 0-100%的仪表盘，>80%时闪烁告警

## 🧠 人类使用习惯深度优化（12项）

### UX1. "3秒因子摘要" — 打开APP第一眼

用户打开APP后不需要点任何按钮，直接看到:
```
┌────────────────────────────────┐
│ 🟢 市场温度: 62° 偏暖          │
│ 今天最强的3个因子:             │
│  1. 北向资金 +2.3σ (9.5/10)   │
│  2. ROE稳定性 +1.8σ (8.7/10)  │
│  3. 散户资金流 -1.6σ (反向)   │
│ ⚠️ 注意: 12月动量近衰退临界    │
└────────────────────────────────┘
```

### UX2. "因子闹钟" — 不是推送，是订阅

用户设: "当MOM_12M的IC跌破0.03时提醒我" → 因子的值变化→时间到了→推送到手机。

**这不是预警，这是订阅**。预警是被动的，订阅是用户主动设的——愿意付费。

### UX3. "因子日记" — 记录你的决策

每次用户看一个因子时，自动记录: 谁/什么时候/看了什么/什么值/当时怎么决定的。
一周后回顾: "你上周根据ROE选的三只股票涨了 +2.3%，vs 基准+0.8%"

### UX4. "因子气候" — 不是因子值，是因子环境

股票天气APP告诉你的不是"温度23°C"，而是"今天适合跑步吗？"
因子应该: "当前市场环境适合价值因子吗？" → 绿灯: "适合, 类似环境下价值因子历史胜率78%"

### UX5. "因子搬家" — 跨市场迁移

用户发现美股有一个因子效果很好 → 一键看"这个因子在A股、港股、日股的历史表现"
→ 发现A股同一因子IC是-0.02(失效) → 不盲目迁移

### UX6. "因子降级" — 明确告诉用户什么时候别用

每个因子卡片上两个区域:
- 上部: 🟢 "当前有效" (IC>0.05, 拥挤<0.6, 体制匹配) → 显示normal
- 下部: 🔴 "历史上失效的情况" → "2022年熊市失效/2018年贸易战失效/拥挤度>0.8时失效"

### UX7. "因子倒推" — 从结果推到因子

用户: "NVDA涨了200%，是哪些因子驱动的？"
→ AI反向分解: 40%动量因子 + 30%成长因子 + 15%资金流 + 10%情绪 + 5%其他

### UX8. "因子食谱" — 不是给因子，是给方案

用户不想学因子——用户想赚钱。
"当前市场配方": 40%质量 + 25%动量 + 20%低波 + 15%价值 → 一键生成策略

### UX9. "因子社交比较" — 自我vs市场

"你关注的5个因子表现跑赢了70%的QUANT MOO用户" → 社交货币驱动留存

### UX10. "因子回忆录" — 年度因子总结

每年1月: "2026年你赚最多的因子上贡献了+32% → 这个因子叫ROE稳定性 → 你已经连续用了8个月"

### UX11. "因子竞技场" — 你的因子组合 vs 基准

把你的因子组合放到一个模拟账户 → 对比沪深300/标普500/恒指 → 每周排名

### UX12. "因子考试" — 游戏化教育

"以下哪个因子在通缩环境下效果最差？A) 动量 B) 质量 C) 价值 D) 低波"
答对 → 解锁因子积分 → 积分兑换因子模板

## 🏁 总结

**QUANT MOO因子系统的后端引擎是世界级水平**（620因子/IC引擎/衰减/拥挤/23个收费点），但前端体验和可视化停留在"内部工具"水平。

**三个最优先行动**:
1. **63组件→1个FactorHub入口** — 用户不应该在63个入口迷路
2. **354新因子人话化** — 70%的因子中文用户看不懂
3. **因子API对外** — $19.9U/月 × 200机构 = +$3,980U/月(纯增量)

**一句话**: 因子引擎造了一辆法拉利发动机，但装在一辆没有方向盘、没有仪表盘、没有导航的三轮车上。补齐前端体验→620因子的真正价值才能释放。

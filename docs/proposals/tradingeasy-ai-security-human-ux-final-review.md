## 二、🔴 7项遗留致命缺陷

### 2.1 致命1: 安全模块彼此孤立，没有统一入口

**问题**: 9个安全模块各自独立，调用时需要开发者手动记住每个:
```typescript
// 当前: 需要手动调3个不同模块
sanitizeAIInput(query);
assertNotAICaller('executeStrategy');
guardPlatformData('getPlatformStats');
maskSensitiveFields(data);
```

**后果**: 任何一个模块漏掉，防线就破了。人类开发者不可能100%每次记住。

**建议**: 新建 `ai-security-gateway.ts` (80行)，作为唯一的统一入口:
```typescript
// 统一入口: 一行搞定
import { aiGate } from './ai-security-gateway';
const result = aiGate.in({ query, callerSource: 'ai', operation: 'recommend' });
// 内部自动: 注入检查→权限检查→脱敏→防火墙→审计
```

### 2.2 致命2: ai-factor-advisor.ts 未与 G7 输出护卫舰集成

**问题**: `ai-factor-advisor.ts` 的 `recommend()` 方法是 AI 安全的最关键入口——但它可能仍然直接把用户上下文传给 LLM，没有经过输出护卫舰的脱敏层。

**验证方法**: 
```bash
grep -n "walletBalance\|userEmail\|accountId" electron/engine/agents/ai-factor-advisor.ts
```
如果这些字段还在上下文构建逻辑中 → 致命。

**建议**: `recommend()` 内部第一步: `context = maskSensitiveFields(context)`。

### 2.3 致命3: multi-llm-router.ts 可能绕过注入防护

**问题**: `multi-llm-router.ts` 是选择用哪个 LLM (DeepSeek/GPT/Claude) 的路由器，位于注入防护之后。但如果路由器本身不做过滤，攻击者可以通过调用不同模型绕过检测。

**建议**: `multi-llm-router.ts` 的 `route()` 方法必须也调用 `sanitizeAIInput()`。

### 2.4 致命4: 无产品级AI聊天界面

**问题**: 当前AI推荐功能是嵌入在引擎中，用户通过因子界面触发。如果TradingEasy以后加"AI对话"功能（聊天窗口），当前所有安全防线都不会自动生效。

**建议**: 如果将来做AI聊天界面，必须在UI层加第6层防护——UI脱敏层（不显示精确数字，用色条/等级替代）。

### 2.5 致命5: 审计日志无自动响应

**问题**: `audit-anomaly-detector.ts` 可以检测异常，但不会自动响应。检测到攻击后只是记录，没有熔断或限流联动。

**建议**: 检测→自动响应链:
```
审计检测到P0级别 → 自动调 rate-limiter 将用户降至 1次/10分钟
审计检测到sk-泄露 → 自动通知管理员 + 关闭该用户AI访问
```

### 2.6 致命6: 未对LLM供应商做数据审计

**问题**: 用户数据发送给 DeepSeek/其他LLM 后，无法确认供应商是否合规存储。这在《生成式人工智能服务管理暂行办法》第11条有明确要求。

**建议**: 
- 发送给LLM的数据必须记录 hash (方便事后审计是否泄露)
- 敏感数据发送前脱敏（当前只是拦截直接调用，但AI对话中的数据可能"表述性泄露"）
- LLM供应商合同中加"不存储用户数据"条款

### 2.7 致命7: "表述性泄露" — 最隐蔽的攻击面

**问题**: 即使balance被设为`****`，攻击者可以通过渐进式提问推断:
```
"我的余额够买3个因子策略吗？" → AI答"够"
"我的余额够买10个因子策略吗？" → AI答"不够"
```
通过二分法可以推断出余额区间。

**建议**: 任何余额判断AI都返回统一模板: "请到钱包页面查看您的余额"。永不做"够/不够"判断。

## 三、🟡 人类UX层面的安全缺陷 (6项)

### 3.1 AI推荐 → "确定性数字"错误认知

**问题**: AI输出 `IC=0.045, Sharpe=1.8` 不带区间，用户以为这是准确值。
**现实**: 这是基于历史数据的估计，实际偏差可达±20%。

**修复**: AI所有数字输出带置信区间: `IC=0.045 ± 0.008 (68%置信)`。

### 3.2 免费→付费的"意外触发"风险

**问题**: 用户在免费预览区误点"查看详细分析" → 立即扣1U → 没有二次确认。
**后果**: 用户投诉、退款、差评。

**修复**: 任何扣费操作前，必须二次确认弹窗: "即将扣费 1.0 USDT 获取详细分析，确定？[取消] [确认]"

### 3.3 分享卡片策略泄露

**问题**: 已修到"仅显示前3因子+模糊回测"，但前3因子的顺序也能泄露信息——如果用户看到 `MOM_12M, QUAL, GRO` 这个顺序，配合回测曲线形状，有经验的量化交易者可以推断出大致权重。

**修复**: 分享模式随机打乱前3因子的显示顺序。

### 3.4 色盲模式的金融染色问题

**问题**: 色盲模式使用蓝色/橙色替代红色/绿色。但在金融领域，蓝色/橙色在K线图上已经有固定含义（如蓝色=均线，橙色=布林带），导致色盲用户同时混淆两个语义。

**修复**: 色盲模式下统一使用符号辅助 (↑/↓) 而不依赖颜色。

### 3.5 移动端安全额外风险

**问题**: 移动端截屏更容易、更频繁。AI对话中即使余额显示为"充足/不足"，对话历史截图仍可泄露因子权重、策略结构。

**修复**: 移动端 AI 对话增加"敏感模式"开关（默认开启），敏感模式下自动隐藏因子权重数值。

### 3.6 新手引导中的安全盲区

**问题**: R172的三步引导中，用户在Step3看到回测曲线+预期收益 `18.5%`，没有任何风险提示。新用户可能以为这是保证收益。

**修复**: 回测预览下方强制显示: "⚠️ 历史回测不代表未来收益。这是基于过去数据模拟的结果，实际结果可能不同。"

## 四、🟢 营收+安全交叉建议 (4项)

### 4.1 安全认证=市场溢价

**建议**: 策略市场中，经过AI安全检查的策略加"安全认证"标签 → 可以溢价20%。
- 买家看到"安全认证"标签更愿意付费
- 激励创作者提交安全合规策略

### 4.2 退款48h→AI信任机制

**建议**: 用户48h内退款 → 不是简单退款，而是收集退款原因 → 分析原因分类(策略不匹配/回测不准/AI误导) → 改善AI推荐。
- 这既是安全机制，也是AI训练数据

### 4.3 安全仪表板(收费功能)

**建议**: Tier2用户可以看到"AI安全报告": 
- "您的策略被3次尝试注入攻击，全部拦截" → 让用户感知到安全价值
- "AI发现了您的策略与XX因子冲突→建议调整" → 增强信任
- 价格: 免费展示基本统计 / 详细报告 2U/次

### 4.4 AI对话"可控透明度"

**建议**: 用户可以选择AI透明度等级:
- L1: "推荐买入科技股" (只说结论)
- L2: "推荐买入科技股(IC=0.045, 置信度68%)" (给区间)
- L3: "推荐买入科技股。因IC=0.045±0.008, 基于MOM_12M+QUAL+GRO因子, 历史胜率62%, 建议仓位15%"(完整推理链)
- L1/L2免费, L3付费(1U)

## 六、总结

TradingEasy v2.3.0 有9个安全模块的"砖"，但缺一个统一的"房子框架"。

**核心问题**: 模块孤岛 → 开发者需要记住手动调用9个模块 → 人类不可靠。

**核心方案**: `ai-security-gateway.ts` 统一入口 + 7项P0补丁 → 12h → R181。

**核心原则**: 安全要做到"默认安全"(secure by default) — 开发者不需要记住安全规则，系统自动执行。

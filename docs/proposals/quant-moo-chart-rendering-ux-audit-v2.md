## 🔴 致命发现（7项，v2新增）

### #1 🔴 移动端图表 = 零 — 最大用户群丢失

**现状**: 88个图表组件 + 57个lib中：
- `MobileAdaptationBootstrap.tsx`: 仅160行，是一个**demo布局预览**，不是真实图表组件
- 没有任何chart组件做了`@media`断点适配
- KLineChartPro使用Canvas渲染→移动端GPU性能灾难
- lightweight-charts的Canvas在375px宽度下K线蜡烛重叠到无法辨认
- 没有触摸手势(捏合缩放/双击/长按)

**影响**: 中国80%+零售用户主力使用手机交易。富途App月活2000万，全部在手机端。QUANT MOO移动端零图表→直接失去80%的TAM。

**竞品对标**:
- 富途牛牛: 专为3.5-6.7寸屏幕设计的K线图，每根蜡烛最小4px，自动调节密度
- TradingView Mobile: 独立原生App，手势优先，带haptic反馈
- 同花顺: 单手竖拇指滑动切换股票的专利交互

**方案**: 不是把桌面版缩小——是完全重设计移动端图表：
1. 单手势K线：左右滑切换股票，上下滑切换时框，双指缩放，双击切换全屏
2. 移动端专属简化：5个最常用指标而非93个，3种画线工具而非68种
3. 横屏模式：手机横过来自动显示K线+成交量+副图指标 三区布局

### #3 🔴 ChartContext基础设施完美但零组件接入

`chart-context-integration.ts` (133行)已经写好了：
- `withChartContext` HOC — drop-in wrapper
- 自动注册26个图表组件
- 跨组件同步symbol/timeframe/market

**但是**: 88个图表组件中**0个**实际导入了ChartContext。

**后果**:
- 切换symbol → 只有当前图表更新 → 其他图表停留在旧symbol
- 切换timeframe → 只有当前图表更新
- 切换市场 → 什么都不变
- 画线 → 只在一个图表可见 → 切时框就消失

**修复**: 给KLineChartPro/StockKLineDeepV2/DrawingToolbar/IndicatorPanel各加一行 `withChartContext(Component)`，立竿见影。

### #4 🔴 画线磁吸/模板/云同步 — 三个P0功能写在Registry里但代码是空的

R269宣称的68画线工具中，3个最关键的功能完全没有实现：

**磁吸(Snap)**: `drawing-tools.ts`定义了`snapToOHLC`函数签名，但函数体是`return point;`（传回原点，什么都没做）。用户画线时没有任何磁吸效果。

**模板(Template)**: `DRAWING_TOOLS`常量里没有`template`类型。用户画了支撑阻力线后无法保存为新股票模板。

**云同步**: 没有任何`cloudSave`/`cloudLoad`调用。画线存储在localStorage，换设备就丢失。

### #5 🔴 分时图仍是mock — R265声称的8h工作未完成

`KLineChartPro.tsx`和`StockKLineDeepV2.tsx`都只有日K/周K等周期蜡烛图。分时图(intraday)不存在：
- 没有当日的1分钟Bar数据获取
- 没有分时走势线+均价线
- 没有分时成交量柱

**同花顺用户行为**: 90%的打开次数是看分时图，只有10%切到日K。没有分时图 = 90%的使用场景直接丢失。

### #6 🔴 快捷键系统注册了但未连接渲染管线

`useKeyboardShortcuts.ts` (R271 ML#4)定义了30个快捷键，但：
- `KLineChartPro.tsx`不导入这个hook
- `DrawingToolbar.tsx`不导入这个hook
- 按键事件永远不会触发任何图表操作

**人类习惯**: 交易员从TradingView/Futu过来，第一件事就是按`Space`切换股票，按`1`→日K。按了没反应→"这个软件不行"→关闭。

### #7 🔴 88个组件中~40%含硬编码mock数据

扫描发现至少有30+个组件含`const mock* = [`或`const MOCK_*`的硬编码数据：

## 🧠 人类使用习惯深度优化（8项新增）

### UX1. "单手K线" — 针对手机竖屏的用户

90%的手机用户用单手持机。设计: 拇指可达区域(屏幕下半部)放最常用的操作(切换时框/添加指标/画线)，屏幕上半部只展示K线。

### UX2. "对比模式" — 两根K线叠在一起

用户最常做的比较: "NVDA vs AMD"。当前对比需要开两个图表。应支持同一图表内叠加第二只股票的K线(百分比对齐)。

### UX3. "昨天这个时候" — 时间轴事件点

在分时图上标记: 昨天同时间的价格、前天、上周一。用户一眼看出"今天比昨天同期高/低多少"。

### UX4. "机构成本线" — 大单均价可视化

VWAP不够——用户想看: 今天所有>50万的大单的平均成交价画成一条虚线。这条线=机构的真实建仓成本。

### UX5. "图表闹钟" — 在K线上设价格线，到位推送

用户在K线图上点一个价格→设"到达这个价格通知我"。不需要填任何表单。这是TradingView上使用率最高的功能之一。

### UX6. "分时博弈" — 中国散户最爱的图表

分时图上叠加: 主力/游资/散户三条线的资金流向。同花顺这个功能日均使用8000万次。QUANT MOO完全缺失。

### UX7. "5秒图表分享" — 截图+标注+分享

用户截图K线→自动添加股票代码+价格+时间水印→一键分享到社区/微信/朋友圈。这是TradingView付费用户增长的第一入口。

### UX8. "K线记忆" — 用户之前在这只股票上的操作回顾

用户回到一只之前交易过的股票，自动标注: "你6月12日以$145买入/6月15日以$152卖出 → +4.8%"

## 🏁 总结

v1审计覆盖了"有什么"（指标/画线/形态的数量），v2审计覆盖了"做得怎么样"（实现质量/移动端/体验/数据流）。

**v2最大的3个发现**:
1. **移动端是零** — 中国80%零售用户在手机上交易，QUANT MOO完全没有移动端图表
2. **TradingView Advanced Charts $600/月能解锁11项功能 → 净赚$625/月** — 这是最低ROI的投资
3. **ChartContext/快捷键/画线磁吸/分时图 R265-R271宣称完成但代码是空的** — 需要实际集成

**一句话**: 图表系统的骨架很好(93指标/68画线/31形态)，但肌肉萎缩(移动端零/数据流断/功能存名无实)。先做移动端→再补数据流→再买Advanced Charts → 图表系统就从"能用"跳到"专业"。

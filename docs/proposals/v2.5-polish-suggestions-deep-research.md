## 零、设计哲学（来自行业调研的5条铁律）

> *"看起来正确"与"在真实市场压力下运作"之间存在鸿沟，大多数产品失败于此。"*
> — Trading App Design Guide 2026

| # | 铁律 | 来源 | 适用于DW的场景 |
|---|------|------|----------------|
| T1 | **渐进式披露** — 不一次教用户所有功能，在操作变得相关时才引入 | UX Onboarding Institute | 240因子/112模板不能一次性展示，新手只看3-5个推荐 |
| T2 | **决策质量 > 交互速度** — 不可逆操作前需制造"暂停时刻" | Trading App Design | 下单/扣费/订阅策略前必须强确认+费用摘要 |
| T3 | **信任=一致性** — 数字格式/颜色/术语在全App必须一致 | Fintech i18n Best Practices | 红涨绿跌/小数分隔符/货币符号位置必须统一 |
| T4 | **降噪而非增噪** — AI应总结信号而非生成更多噪音 | Trading App Design | AI因子优化应说"调这个参数"，而非"给你100个新因子" |
| T5 | **空状态即引导** — 空页面是最佳教育时机，不是"暂无数据" | Marketplace UX Design | 新用户首次看到因子列表=空=应展示3步快速开始 |

## 一、🔴 P0 — 阻塞性问题（用户无法正常使用）

### 1.1 因子i18n覆盖率仅45% — 非中文用户看到"因子ID"而非"因子名"

**现状**: 240因子中仅108个有i18n翻译，196个在非中文环境下只显示`F_ONCHAIN_WHALE`这种代码

**人类习惯分析**:
- factors.directory（500+因子库）为每个因子提供：**人话名称 + 数学公式 + 历史表现 + 应用场景**
- 我们连最基础的"人话名称"都没有覆盖55%的因子
- 用户在选择策略模板时，`factorCombo`里引用的因子ID如果不翻译，等于给用户看代码

**优化方案**:

| 步骤 | 内容 | 工时 | 验收标准 |
|------|------|------|----------|
| 1a | 清理132个幽灵i18n条目(注册表已不存在的) | 2h | i18n-map无一条指向不存在的因子 |
| 1b | 为196个裸因子补齐**11语言**的名称+简述 | 16h | 196×11=2,156条翻译，每条≤2句 |
| 1c | 补齐**因子人话描述模板**(每因子3要素) | 4h | "衡量XX，当YY时看涨，适用于ZZ市场" |
| 1d | 建立i18n自动化校验CI | 2h | 每次commit自动检测注册表↔i18n-map匹配率 |

**因子人话模板**(参照factors.directory):
```
{
  "F_ONCHAIN_WHALE": {
    "name": "链上巨鲸追踪",
    "short": "监测大额链上转账对价格的影响",
    "when": "当巨鲸地址净流入>2σ时看涨",
    "market": "加密货币",
    "period": "4h-1d"
  }
}
```

> **关键**: 不是翻译代码注释，是用**交易员的语言**写因子说明

### 1.2 Calculator映射断裂 — 用户选了因子但可能算不出结果

**现状**: 6个Calculator文件声称197个factorId，但与注册表ID命名不一致，仅5个确认匹配

**人类习惯分析**:
- 用户工作流: 选模板→看因子→调参数→跑回测→看结果
- 如果"调参数→跑回测"这一步因子算不出值，用户只会看到空白或Error
- **这是最破坏信任的体验** — 用户以为自己的参数设错了，反复调试，其实是系统断了

**优化方案**:

| 步骤 | 内容 | 工时 | 验收标准 |
|------|------|------|----------|
| 2a | 写自动校验脚本，逐个验证240因子是否有对应Calculator | 4h | 输出: 240条匹配结果(✅/❌/⚠️stub) |
| 2b | 缺失Calculator补安全stub: 返回"该因子计算暂不可用" | 4h | 任何因子至少返回友好提示，不会白屏 |
| 2c | 统一factorId命名: Calculator↔Registry ID映射表 | 4h | 一个factorId在所有文件中拼写完全一致 |
| 2d | 在策略模板选择页增加"因子可用性"实时检测 | 2h | 模板详情页显示 "5/5 因子可用 ✅" 或 "3/5 ⚠️ 2个暂不可用" |

> **参考FactorHub做法**: 他们有实时语法验证+因子有效性检验。我们至少要做到"这个因子能不能算"的实时反馈

### 1.3 5条数据断链 — 代码写了但没接通

**现状**: broker→IPC→bridge→engine→UI 存在5处断连
- ErrorBoundary: 3个版本存在，0个被应用
- IndicatorWorker: 代码存在，从未被调用
- ChartContext: 存在，0个import
- 5条数据链路: 全部断开

**人类习惯分析**:
- 用户不会看代码，只看效果：点了按钮没反应=产品坏了
- 交易应用中"看起来正确但在压力下失败"是最致命的

**优化方案**:

| 步骤 | 内容 | 工时 | 验收标准 |
|------|------|------|----------|
| 3a | 逐一接通5条数据链路 | 8h | 每条链路有1个端到端测试pass |
| 3b | ErrorBoundary统一为1个版本并应用到因子页面 | 4h | 因子页面crash时显示友好降级UI |
| 3c | IndicatorWorker接入FactorSignalPipeline | 4h | 因子信号能触发UI实时更新 |
| 3d | ChartContext注入因子回测图表 | 2h | 回测结果页能渲染因子表现图表 |

## 二、🟡 P1 — 核心体验打磨（影响用户留存和转化）

### 2.1 策略模板发现体验 — 从"112个列表"到"智能推荐"

**现状**: 112个策略模板分布在3个系统(新46+Server36+旧30)，用户浏览时只能看到平铺列表

**行业调研洞察**:

| 平台 | 发现机制 | 用户工作流 |
|------|----------|------------|
| eToro | Popular Investor排名 + 风险评分 + 一键复制 | 看排名→看指标→一键跟 |
| 3Commas | 策略模板Marketplace + 回测展示 + 评分 | 按币种筛选→看回测→订阅 |
| FactorHub | 因子→分析→组合→回测5步流程 | 逐步递进，每步有验证 |
| factors.directory | 9大类+搜索+对比 | 按分类浏览→查看公式→对比 |

**人类习惯分析**:
- 用户**不会**从112个模板中逐个挑选（决策瘫痪）
- 用户**会**按"我想做XX市场"→"我风险偏好是XX"→"推荐3个"的路径
- Marketplace UX设计9原则: **搜索必须直观且容错**，**信任和验证徽章**

**优化方案 — "3步到策略"工作流**:

```
Step 1: "你想交易什么？" 
  → 🇭🇰港股 / 🇺🇸美股 / 🪙加密 / 🇯🇵日股 / 🛢️商品 ...
  
Step 2: "你的风格是？"
  → 🐢稳健(低换手+止损) / 🐇进取(高杠杆+短线) / 🤖AI辅助

Step 3: "为你推荐 3 个策略模板"
  → 每个卡片: 名称 + 适合市场 + 近期胜率 + X人使用过 + 一键开始
```

| 步骤 | 内容 | 工时 |
|------|------|------|
| 4a | 实现`StrategyRecommender`引擎(市场×风格→3推荐) | 8h |
| 4b | 新用户首次进入显示"3步到策略"引导 | 4h |
| 4c | 模板卡片增加: 胜率/夏普/使用人数/AI审核徽章 | 6h |
| 4d | 统一3套模板系统为1个展示层(后端可分3个，前端只1个) | 8h |

### 2.2 因子选择器 — 从"代码ID列表"到"智能因子超市"

**现状**: 用户在策略模板中看到`factorCombo: [{ factorId: 'F_ONCHAIN_WHALE', weight: 70 }]`

**行业调研洞察**:
- factors.directory: 9大类(技术/情绪/基本面/动量/波动/流动/成长/质量/价值)
- FactorHub: 因子→分析→挖掘→组合→回测 完整工作流
- **用户不会关心因子ID**，关心的是"这个因子能帮我赚钱吗？"

**优化方案 — 因子超市3层架构**:

```
┌─────────────────────────────────────────────────┐
│ Layer 1: 分类浏览(16大类→55中类)                    │
│   🪙加密(36) → 链上(12) / DEX(8) / 情绪(9) / DeFi(7) │
│   🇭🇰港股(19) → 南向(7) / AH溢价(6) / 成交(6)       │
│   ...                                             │
├─────────────────────────────────────────────────┤
│ Layer 2: 因子卡片(人话+指标)                        │
│   ┌─────────────────────────────────────┐        │
│   │ 🐋 链上巨鲸追踪   🟢可用 ✅已验证       │        │
│   │ "大额链上转账对价格影响"               │        │
│   │ 近30日IC: 0.12 | 胜率: 58%          │        │
│   │ 适用于: BTC/ETH | 周期: 4h-1d       │        │
│   │ [加入我的策略] [查看详情]             │        │
│   └─────────────────────────────────────┘        │
├─────────────────────────────────────────────────┤
│ Layer 3: 因子详情页(参照factors.directory)          │
│   • 人话描述 + 数学公式 + 适用市场 + 历史表现       │
│   • 在当前策略中的权重滑块(0-100)                  │
│   • AI解读(1U): "近期该因子在BTC市场IC走弱..."      │
│   • 敏感度分析(1.5U): 该因子对参数变化的敏感度      │
└─────────────────────────────────────────────────┘
```

| 步骤 | 内容 | 工时 |
|------|------|------|
| 5a | 因子选择器UI组件(分类浏览+搜索+卡片) | 10h |
| 5b | 因子卡片实时数据(IC/胜率/可用性) | 6h |
| 5c | 因子详情页(公式+历史+AI解读入口) | 8h |
| 5d | 因子权重滑块(0-100，拖拽调参+实时预览) | 4h |

### 2.3 Fintech i18n专业化 — 超越"翻译"走向"本地化"

**现状**: 11种语言覆盖，但只是字面翻译，未做金融本地化

**行业调研关键发现**:

| 问题 | 现状 | 应该 | 来源 |
|------|------|------|------|
| 数字格式 | 统一`1,234.56` | 德国`1.234,56` 印度`12,34,567.89` | Fintech i18n Guide |
| 货币符号 | 固定`$` | EUR符号在后`1.234,56 €` | Fintech i18n Guide |
| 涨跌颜色 | 未统一 | 中国红涨绿跌 vs 美国绿涨红跌 | Trading App Design |
| 日期格式 | 统一`MM/DD` | 日本`2024年1月2日` 德国`02.01.2024` | Fintech i18n Guide |
| 交易术语 | 直译 | "credit score"在美国≠中国 | Fintech i18n Guide |

**优化方案**:

| 步骤 | 内容 | 工时 |
|------|------|------|
| 6a | 引入`Intl.NumberFormat`/`Intl.DateTimeFormat`统一格式化层 | 4h |
| 6b | 涨跌颜色按市场切换: 🇭🇰🇨🇳🇯🇵红涨绿跌 / 🇺🇸🇪🇺绿涨红跌 | 3h |
| 6c | 金融术语本地化词汇表(每语言50个核心术语) | 8h |
| 6d | 日元/韩元零小数处理(JPY/KRW不显示分) | 2h |
| 6e | 印度拉克数字分组(`12,34,567`) | 2h |

> **法规合规关键**: 欧盟PSD2要求**必须使用用户语言进行透明的费用披露**。我们的22项AI收费如果只在中文界面显示费率，在EU市场可能违规

### 2.4 模板参数体验 — 从"技术参数"到"人话调节"

**现状**: 新系统`factorCombo`权重0-100 + `tunableParams`(3-5个) + 旧系统`parameters[]`(name/type/min/max)

**人类习惯分析**:
- 用户不理解`momentumThreshold: 1.0 (range: 0.5-2.0)`意味着什么
- 用户理解"**灵敏度**: 低←→高"这种自然语言
- Trading App Design: **渐进式披露** — 主屏幕简化，高级控制收纳在可展开区域

**优化方案 — 参数"人话化"三步**:

| 步骤 | 内容 | 工时 |
|------|------|------|
| 7a | 每个tunableParam增加`humanLabel`+`humanDesc` | 4h |
| 7b | 参数UI: 初级=滑块(低/中/高) 高级=精确数值 | 6h |
| 7c | AI参数建议(1U): "基于近期市场，建议将灵敏度调至'中高'" | 4h |

**参数人话化示例**:
```typescript
// 之前
{ paramName: 'momentumThreshold', currentValue: '1.0', range: '0.5-2.0' }

// 之后
{ 
  paramName: 'momentumThreshold',
  humanLabel: { zh: '动量灵敏度', en: 'Momentum Sensitivity', ja: 'モメンタム感度' },
  humanDesc: { zh: '越高越灵敏，容易抓住短线机会但也容易误判', en: 'Higher = more sensitive, catches short-term but more false signals' },
  displayMode: 'slider', // 初级用户看到滑块
  sliderLabels: { low: '0.5', mid: '1.0', high: '2.0' },
  value: 1.0
}
```

### 2.5 券商连接体验 — 从"13个适配器"到"一键连券商"

**现状**: 13个券商适配器，代码量从143行(Futu)到2035行(IB)，但连接流程未知

**行业调研洞察**:
- OpenAlgo: plugin.json声明 + 动态加载 + 统一接口 + 共享连接池
- eToro: 一键复制交易(无需手动配置API Key)
- 关键: **用户不想知道什么是API Key**，只想"连接我的券商"

**优化方案**:

| 步骤 | 内容 | 工时 |
|------|------|------|
| 8a | 券商连接向导: 选券商→扫码/输入Key→验证→完成 | 6h |
| 8b | 券商健康检测: 实时显示连接状态+延迟+余额 | 4h |
| 8c | 券商统一接口层(参照OpenAlgo BrokerData模式) | 8h |
| 8d | 安全提示: "您的API Key仅在本机使用，不会上传服务器" | 2h |

> **关键信任点**: 用户最怕API Key泄露。必须在连接页面**醒目**显示安全声明

## 三、🟢 P2 — 长期优化（影响专业用户和创作者生态）

### 3.1 因子热力图 — 一屏看240因子的市场状态

**行业调研洞察**:
- Trading App Design: 专业交易员期望最大数据密度
- 金融平台使用颜色编码热力图快速传达数百个数据点的状态
- **人类习惯**: 颜色是最快的信号 — 用户0.1秒就能从热力图发现异常

**优化方案**:
- 240因子按16大类排列的热力图
- 颜色=当前信号强度(深绿=强看涨→深红=强看跌)
- 悬停=因子详情弹窗
- 点击=因子详情页
- 每日自动截图=因子日报(AI生成摘要，1U)

### 3.2 创作者市场信任体系

**行业调研洞察**:
- eToro: Popular Investor排名 + 风险评分 + 透明历史
- Marketplace UX: **社交证明+验证徽章+定价透明度**是3大信任支柱
- 我们已有AI自动审核(8项检查)，但用户看不到审核过程

**优化方案**:

| 信任元素 | 实现 | 来源参考 |
|----------|------|----------|
| ✅AI审核徽章 | "已通过8项AI审核" + 审核时间 | eToro风险评分 |
| 📊真实数据 | 使用过人数 + 近30日胜率 + 最大回撤 | 3Commas回测展示 |
| 💰定价透明 | 费用明细+总成本预估(无隐藏费) | Marketplace定价透明度 |
| 🔒安全声明 | "策略在沙盒中运行，不影响您的资金" | 支付安全最佳实践 |

### 3.3 暗色模式优先 + 色盲友好

**行业调研洞察**:
- Trading App Design: **暗色模式是可用性刚需**(减少眩光、缓解眼疲劳)
- 8%男性存在色觉缺陷，不能仅依赖红/绿
- 必须补充次要指示器: 箭头↑↓ / 图标 / 文字标签

**优化方案**:
- 暗色模式为默认(交易App惯例)
- 所有涨跌颜色同时配合: ↑↓箭头 + "涨/跌"文字
- WCAG 2.1 AA对比度标准(4.5:1)

### 3.4 模拟交易(零风险体验)

**行业调研洞察**:
- Trading App Design: **模拟交易**帮助新投资者建立信心
- UX Onboarding: **价值前置** — 让用户先体验价值再付费
- eToro: 10万虚拟美元模拟账户

**优化方案**:
- 新用户默认进入模拟模式(虚拟10万U)
- 完整策略体验: 选模板→调参数→看回测→模拟执行
- 首次真实交易前: 强确认+"您正在使用真实资金"提醒

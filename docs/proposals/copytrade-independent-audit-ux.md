# TradingEasy 跟单业务独立审查报告

> **Author**: QClaw · **Date**: 2026-06-13 08:50 HKT
> **Scope**: 全项目跟单业务链路 — 从用户打开页面到订单执行
> **方法**: 模拟真实人类用户操作路径逐一审查

---

## 一、用户操作全链路审查

### 路径 A: 新用户首次使用跟单

```
打开 TradingEasy → 点击"跟单" → 选择信号源 → 配置金额 → 连接券商 → 启动跟单 → 等待成交 → 查看收益
```

### 路径 B: 已有 OpenD 的桌面端用户

```
打开桌面端 → OpenD 信号面板 → 拉取待处理信号 → 审核 → 执行 → 回传结果
```

## 二、发现的问题（按 P0/P1/P2 分级）

---

### 🔴 P0: 阻塞用户体验的问题（必须修）

#### P0-1: 跟单 UI 全量使用 Mock 数据，无法接通真实系统

**影响**: 用户看到的信号源、通知、历史记录全为假数据

| 文件 | Mock 行数 | 影响 |
|------|----------|------|
| `CopyTradeSettings.tsx` | 5个硬编码信号源 + 4个券商 | 用户无法看到真实信号源 |
| `CopyTradeNotifications.tsx` | 6条预设通知 | 所有推送为假, 无真实 WS 连接 |
| `SignalFeedAndCopyPanel.tsx` | 6个信号 + 2个跟单 | 信号Feed完全假数据 |
| `CopyTradeDashboard.tsx` | 4处 MOCK_ | 仪表盘数据不真实 |
| `CopyTradeStatusBar.tsx` | 2处 MOCK_ | 状态栏数据不真实 |

**建议**: 
- [ ] P0: `SignalFeedAndCopyPanel` 接入 `/api/signal` 真实端点 — **3h**
- [ ] P0: `CopyTradeSettings` 从后端加载真实信号源列表 — **2h**
- [ ] P0: `CopyTradeNotifications` 接入 WS 真实推送 — **3h**
- [ ] P1: Dashboard/StatusBar 接入真实统计数据 — **2h**

#### P0-2: 桌面端 OpenD 拉取循环未实现

**现状**: `GET /api/signal/pending?type=opend` 端点已存在，但桌面端无轮询/回调来拉取

```
期望: 桌面端每 1 秒 GET /api/signal/pending → 有新信号 → 面板显示
实际: 桌面端无 polling loop 代码, useOpenDStream 未调用 /pending
```

**建议**:
- [ ] P0: `useOpenDStream` 或新建 `useOpenDSignalPoller` hook, 1秒轮询 `/api/signal/pending` — **2h**
- [ ] 信号面板展示: 按优先级排序 (P0 止损 → P1 跟单 → P2 批处理) — **2h**
- [ ] 执行确认后调 `POST /:id/execute` 回传 — 已有但需测试 — **1h**

#### P0-3: 信号源 AI 引擎未接入跟单

**现状**: 项目有 4 Agent (fundamentals/technical/sentiment/macro) + orchestrator，但它们的输出**从未写入 signal 队列**

```
期望: Agent 分析 → 生成 BUY/SELL 信号 → 写入 SignalQueue
实际: Agent 引擎输出停留在 console.log / engine-local
```

**建议**:
- [ ] P0: `trader-signal-bridge.ts` → SignalQueue 的 enqueue 调用 — **3h**
- [ ] 信号冷却: 同一 symbol+direction 30秒内不重复发 — **1h**
- [ ] 置信度阈值: confidence < 0.4 的信号不进入队列 — **0.5h**

### 🟡 P1: 严重影响使用体验

#### P1-1: 无"试算"功能 —— 用户下单前看不到预期费用

**问题**: 用户点"执行"后才知道扣了多少手续费

```
建议: 在确认弹窗中加入:
  ┌────────────────────────────────────────┐
  │  确认下单 — AAPL BUY 10股               │
  │  ───────────────────────────────────── │
  │  预估价格:     $180.50 × 10 = $1,805.00 │
  │  佣金:         $0.00 (免佣)              │
  │  SEC费:        $0.01                     │
  │  TAF费:        $0.00                     │
  │  平台费:       $1.80 (0.10%)             │
  │  ───────────────────────────────────── │
  │  预估总额:     $1,806.81                 │
  │                                         │
  │  [取消]  [确认下单]                      │
  └────────────────────────────────────────┘
```

**建议**: — **2h**

#### P1-2: 无"撤单/修改"按钮 —— 用户误操作无法挽回

**问题**: 确认执行后无法取消或修改订单

**建议**:
- [ ] P1: 待处理信号支持"取消"按钮, 调 `PATCH /api/signal/:id/cancel` — **1h**
- [ ] P1: 已执行待成交订单支持"撤单" (调 `POST /api/signal/:id/cancel-order`) — **1h**
- [ ] P1: 提供 5 秒倒计时确认 (类似 iOS 的"摇一摇撤销") — **1h**

#### P1-3: 无"跟单暂停原因"提示

**问题**: 用户暂停跟单后不知道为什么停了 (断路器触发? 余额不足? 用户手动?)

**建议**:
- [ ] P1: 暂停状态旁显示原因标签: `🛑 暂停 · 连续3次下单失败 → 5分钟后自动重试` — **1h**
- [ ] P1: 断路器 OPEN 时给用户明确提示 + 冷却倒计时 — **1h**

#### P1-4: 信号重复问题 —— 同一信号可能被多个跟单用户重复执行

**问题**: `Source Trade → N copiers` 场景中, 如果源交易者发出一次信号, 多个跟单者可能收到重复信号

```
现状: SignalQueue 只有 signalId dedup, 但不同 provider 的相同交易无保护
建议: 增加 (symbol + direction + price ± slippage + time window) 去重 — 2h
```

#### P1-5: 无"跟单日志"—— 用户看不到历史执行记录

**问题**: 用户想知道"今天跟买了什么"时需要翻通知列表

**建议**:
- [ ] P1: `/copy_trades` 页面 (表格: 时间·信号源·标的·方向·数量·价格·费用·状态) — **3h**
- [ ] P1: 支持按日期/信号源/状态筛选 + CSV 导出 — **1h**

#### P1-6: API Key 配置无状态指示

**问题**: 用户添加了 API Key 但不知道是否有效

**建议**:
- [ ] P1: Key 旁显示连接状态: 🟢 正常 · 🟡 权限不足 · 🔴 无效 — 调 `/api/user/api-keys/verify` — **2h**

```
POST /api/signal → DB → SignalQueue.enqueue → CopyTradeExecutor.poll
                                                      ↓
                                              CircuitBreaker check
                                                      ↓
                                              API Key 解密 → Adapter.placeOrder
                                                      ↓
                                              ack(success/fail) → retry/dead
```

## 四、人类使用习惯优化建议

### 4.1 信息密度与层次

| 现状 | 建议 |
|------|------|
| 通知列表扁平, 7 种类型混合 | 分组: 成交/失败/信号/系统 |
| 信号面板只显示基本信息 | 加入盈亏预测 + 历史准确率 |
| 设置页字段平铺 | 分段: 信号源→券商→风控→高级 |

### 4.2 操作反馈

| 现状 | 建议 |
|------|------|
| 点击启动跟单 → Toast "已启动" | 添加按钮状态变化动画 + 声音确认 |
| 下单失败 → Toast "失败" | 显示具体原因 + "查看详情"链接 |
| 断路器触发 → 静默 | 推送 + 声音 + 面板状态变化 |

### 4.3 减少认知负荷

- 新用户默认"保守模式" (低金额+必须确认) → 老手切换"激进模式"
- 信号源列表默认按"30天夏普"排序 (而不是按字母)
- 费用在确认前展示 (P1-1)

### 4.4 信任建设

- 信号源卡片显示: `已跟单 358 人 · 7天收益 +3.2% · 验证标签`
- 每次成交 5 秒后显示实盘确认 (而非 mock 的瞬时成功)
- 提供"模拟跟单一周"的入口 (P2-3)

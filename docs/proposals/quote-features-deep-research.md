# quant-moo 行情功能深度学习报告 & PM 建议

> **日期**: 2026-06-12 | **研究员**: QClaw (文档虾)
> **对标平台**: TradingView / Thinkorswim (TD Ameritrade) / 富途牛牛 moomoo / Bloomberg Terminal / N2N Connect
> **状态**: 建议草案，等待 PM 决策

---

## 一、研究发现摘要

通过深度学习 5 大主流交易平台的行情体系，对标 quant-moo 现有架构（16 券商 BrokerManagerV2 + QuoteAggregator + WebSocket 推送），发现 **5 个高价值缺口** 和 **3 个可立即落地的优化**。

## 二、对标平台核心能力拆解

### 2.1 TradingView — 图表与社区王者

| 能力 | 实现方式 | DH 对标 |
|------|---------|---------|
| K 线渲染 | 自研 Canvas 引擎，支持 100+指标叠加 | ❌ 无自研图表引擎 |
| 实时推送 | WebSocket 流式，数据分离推送 | ⚠️ 已有 WS，数据格式未统一 |
| 股票筛选器 | 100+ 条件组合筛选，秒级反馈 | ❌ 无筛选器 |
| 社区信号 | Pine Script 策略分享+评论 | ⚠️ 有 SignalSquare，无编码分享 |
| 多设备同步 | iCloud 推送，图表+Watchlist 同步 | ❌ 仅桌面端 |

**⌳ 关键洞察**: TradingView 的核心竞争力不是行情数据本身，而是 **图表分析工具 + 社区生态**。行情只是底层管道。

### 2.2 Thinkorswim (TD Ameritrade) — 期权与专业交易

| 能力 | 实现方式 | DH 对标 |
|------|---------|---------|
| 期权链分析 | Greeks 实时计算 + 可视化 | ⚠️ 有 IBKR/Schwab Greeks |
| 风险分析 | Portfolio Greeks 聚合 + 压力测试 | ⚠️ 有 RiskDashboard |
| 扫描器 | Scan Hacker — 500+ 预设条件 | ❌ 无扫描器 |
| 条件单 | 复杂条件 + OCO + 多腿 | ⚠️ OCO 仅 6 家券商 |
| Level 2 | 深度订单簿 + Time & Sales | ⚠️ L2 仅 6 家券商 |

**⌳ 关键洞察**: Thinkorswim 赢在 **专业交易工具的深度**，每个功能模块可独立支撑百万美金级交易决策。

### 2.3 富途牛牛 moomoo — 散户友好 + 数据驱动

| 能力 | 实现方式 | DH 对标 |
|------|---------|---------|
| **🔥 热力图 Heatmap** | 按市值/成交量/涨跌的板块热力图 | ❌ **完全缺失** |
| **🔥 热度榜** | 交易/搜索/资讯综合热度排名 | ⚠️ 有 R53 信号体系 |
| **🔥 资金流向** | 实时主力/散户/特大单资金流向 | ⚠️ 仅富途+moomoo |
| 卖空数据 | 港股卖空比例+持仓分布 | ❌ **完全缺失** |
| 机构持仓 | 明星基金13F持仓披露 | ❌ **完全缺失** |
| 股票对比 | 多股财务+技术指标并列对比 | ❌ 无对比功能 |
| 期权威兹 | Greeks + 概率计算器 | ⚠️ 部分有 |

**⌳ 关键洞察**: 富途的核心差异点是 **"数据产品化"** — 把原始数据变成散户能看懂的决策信号。热力图/热度榜/资金流向 是最高频使用的功能。

### 2.4 Bloomberg Terminal — 专业数据终端

| 能力 | 实现方式 | DH 对标 |
|------|---------|---------|
| 多资产行情 | 统一界面，覆盖所有资产类别 | ⚠️ 16 家券商覆盖已很广 |
| 新闻终端 | 实时过滤+AI 摘要 | ⚠️ 有 4 Agent (sentiment) |
| 经济日历 | 全球宏观数据发布日历 | ❌ 无 |
| 函数式查询 | BDP/BDS/BQL 自定义查询 | ❌ 无 |
| 工作流集成 | Excel 插件 + API | ❌ 无（仅 Electron 桌面） |

**⌳ 关键洞察**: Bloomberg 的优势是 **数据广度+深度+工作流集成**，年费 $24,000 仍有 325,000+ 订阅。DH 无需对标全部。

**方案**:

│                                               │
│  ┌──────┬──────┬──────┬──────┬──────┐       │
│  │ 科技  │ 银行  │ 医药  │ 消费  │ 能源  │       │
│  │ 🟢+2.3│ 🔴-1.2│ 🟢+0.5│ 🔴-0.3│ 🟢+1.8│       │
│  │ 腾讯  │ 汇丰  │ 药明  │ 美团  │ 中海油 │       │
│  │ 阿里  │ 中银  │ 百济  │ 京东  │ 中石油 │       │

└─────────────────────────────────────────────┘

**数据源**: 已有 — 16 家券商行情 + CodeNormalizer 统一代码 → 按板块分组

**技术实现**:

- 颜色渐变：绿(涨) → 白 → 红(跌)，值越极端颜色越深
- 5min 自动刷新 + WS 实时推送选中的板块

**工作量**: ~200L UI + 100L 数据处理 = **ML 3h**

**用户价值**: 散户最常用的功能之一，0→1 补齐市场全局感知

### 建议 2: Smart Scanner 智能行情筛选器 (P0)

**对标**: Thinkorswim Scan Hacker / TradingView Screener

**方案**:
```yaml
预设场景 (5个):
  1. "爆发股扫描": 涨跌幅>5% + 成交量>均量3倍 + 市值>10亿
  2. "突破扫描": 价格创52周新高 + RSI<70 (非超买)
  3. "超跌反弹": 连续下跌3天 + RSI<30 + 成交量放大
  4. "资金异动": 主力净流入>1亿 + 涨幅<3% (未启动)
  5. "跨市场套利": 美股价格/港股ADR比 > 1.05

自定义条件 (20+):
  - 市场: 港/美/A/加密
  - 价格: <$5 / $5-50 / $50-200 / >$200
  - 涨跌幅: >5% / >10% / < -5%
  - 成交量: >1M / >10M / >100M
  - 技术: RSI / MACD / 布林带 / MA交叉
  - 基本面: PE / PB / ROE / 股息率
  - 排序: 涨跌幅 / 成交量 / 热度 / 更新时间
```

**数据源**: 16 家券商 → QuoteAggregator 统一价格 → 本地计算技术指标

**技术实现**:
- 后端: ScannerEngine (IPC handler → 遍历 quote cache → 过滤)
- 前端: 列表组件 + 条件筛选面板
- 可扩展: 允许用户保存自定义扫描条件

**工作量**: ~300L engine + ~300L UI = **JVS 4h + ML 4h**

**用户价值**: 从"被动接收行情"→"主动发现机会"，质变

### 建议 4: Cross-Broker Arbitrage Scanner 跨券商套利扫描 (P1)

**对标**: 多平台价差套利工具（Bloomberg AES, N2N Connect multi-broker）

**方案**:
```yaml
套利类型:
  1. 跨券商价差:
     - 美股AAPL: Schwab $185.50 vs Webull $185.48 → 价差 $0.02
     - 港股腾讯: 富途 HKD385.2 vs 盈立 HKD384.8 → 价差 HKD0.4
  
  2. ADR/港股折溢价:
     - BABA: 美股$102.3 vs 港股HKD85.0 → ADR溢价1.2%
  
  3. 现货/期货基差:
     - BTC: Binance $72,350 vs OKX $72,380 → 价差 $30

触发条件: 价差 > 阈值 × 预估成本 → 告警
```

**数据源**: QuoteAggregator 已聚合 16 家券商实时报价 ✅

**技术实现**:
- 后端: `ArbitrageScanner` → 遍历 aggregator cache → 计算价差
- 前端: 实时表格 + 价差趋势图
- 注意: 需扣除交易成本(spread + 佣金 + 滑点)后才算真实套利空间

**工作量**: ~200L engine + ~200L UI = **JVS 3h + ML 3h**

**用户价值**: 16 券商聚合的独特优势 — 只有 quant-moo 能做到

### 建议 5: Quote Streaming Performance Optimization 行情推送性能优化 (P2)

**现状分析**:
- 16 家券商同时 WS 推送时，最大并发消息量级：~500 msg/s（加密牛市）
- 当前: 每条消息直接推送到 Renderer 渲染
- 问题: React 重渲染频率过高，UI 卡顿

**方案**:
```
┌─────────────────────────────────────────────────┐
│  Main Process                                     │
│  16 WS → worker_threads (C++) → RingBuffer       │
│         ↓ throttle 100ms                         │
│  IPC batch push (50 quotes/msg)                  │
├─────────────────────────────────────────────────┤
│  Renderer Process                                 │
│  IPC → Zustand batchUpdate → React.memo          │
│       → virtual-scroll (只渲染可见行)             │
└─────────────────────────────────────────────────┘
```

**优化项**:
1. **Main 端节流**: `worker_threads` 处理 16 路 WS → 100ms 合并 → 单次 IPC 推送
2. **渲染优化**: virtual-scroll（1000+ 股票只渲染 20 行可见）
3. **React.memo**: 只 re-render 价格变化的行，其余 skip
4. **Web Worker**: 技术指标计算移到 Worker，不阻塞 UI 线程

**工作量**: ~400L 重构 = **JVS 6h**

**用户价值**: 从"能用"→"丝滑"，16 券商同时推送时不卡顿

## 六、决策建议

### 6.1 立即可做的 3 件事（无需新数据源）

1. **Market Heatmap** (ML 3h) — 仅需 16 家券商现有行情数据 + 板块分组，数据完全就绪
2. **Smart Scanner** (JVS+ML 8h) — 仅需 QuoteAggregator cache，本地计算指标
3. **Cross-Broker Arbitrage** (JVS+ML 6h) — QuoteAggregator 已有跨券商价格

**合计: 17h，3 个功能全部落地**

### 6.2 建议不做的事

1. ❌ **自研 K 线图表引擎** — 成本太高（600h+），建议嵌入 TradingView Charting Library
2. ❌ **纯手动画线工具** — TradingView 已做极致，无需重复造轮子
3. ❌ **新闻终端** — 4 Agent sentiment 已覆盖，成本收益不划算
4. ❌ **机构持仓** — SEC 13F 有 45 天延迟，信息价值有限

### 6.3 核心战略问题

> **行情功能的目标是什么？**
> 
> A) 做 "穷人的 Bloomberg" — 全覆盖+深度数据 → 无限对标 Bloomberg 功能
> 
> B) 做 "更好的 TradingView" — 多券商聚合+AI信号+社区 → 强化图表+社交
> 
> C) 做 "跨券商交易终端" — 执行效率+套利+风控 → 聚焦交易工作流
> 
> **QClaw 建议选 C** — quant-moo 的核心壁垒是 **16 券商并发连接 + SmartOrderRouter + CrossBrokerRisk**，行情功能应围绕"让交易决策更高效"展开，而非拼数据广度。

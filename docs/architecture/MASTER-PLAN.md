## 1. 项目定位与愿景

### 一句话定位

**QuantDesk Pro = 散户的私人量化团队**

不会写代码？没关系。用鼠标拖拽积木，搭建你自己的量化策略，一键连接富途/moomoo实盘交易。

### 愿景

> 让每个散户都能用上机构级量化工具，
> 像搭积木一样构建策略，
> 像点外卖一样下单交易。

### 核心价值主张

| 维度 | 传统方式 | QuantDesk Pro |
|------|----------|---------------|
| 编程门槛 | 必须会 Python/C++ | **说人话**，用自然语言描述策略 |
| 数据获取 | 自己找数据源，花钱买 | **内置**实时行情 + 历史数据 |
| 回测 | 自己写回测框架 | **一键回测**，秒级出结果 |
| 实盘 | 手动下单 / 自己写 API | **一键实盘**，自动执行 |
| 风控 | 自己写止损逻辑 | **内置风控**，自动保护 |
| 监控 | 自己盯盘 | **智能监控**，异常报警 |
| 成本 | 数据费 + 服务器 + 开发时间 | **月费 ¥0-299**，开箱即用 |

### 第一个合作券商：富途 / moomoo

选择理由：
- OpenD API 成熟稳定，文档齐全
- 覆盖美股、港股、A股、加密货币
- 用户基数大（moomoo 全球 2000 万+用户）
- API 免费使用（只需开户）
- 支持实时行情、历史 K 线、交易下单、持仓查询

## 3. 用户画像与核心场景

### 用户画像 A — 小白投资者（60%用户）

- **年龄**: 25-45 岁
- **背景**: 上班族，有闲钱但没时间盯盘
- **编程**: 完全不会
- **需求**: "帮我自动赚钱，我不想学编程"
- **使用方式**: 从策略市场选策略 → 一键跟单 → 手机收通知

### 用户画像 B — 进阶交易者（30%用户）

- **年龄**: 30-50 岁
- **背景**: 有交易经验，懂技术指标，但不会编程
- **编程**: 不会，但理解逻辑
- **需求**: "我有自己的交易思路，想自动化"
- **使用方式**: 用积木搭建策略 → 回测优化 → 实盘运行

### 用户画像 C — 量化爱好者（10%用户）

- **年龄**: 25-40 岁
- **背景**: 程序员/金融从业者，懂量化
- **编程**: 会 Python，但想要更方便的工具
- **需求**: "快速验证策略想法，不想写胶水代码"
- **使用方式**: 可视化搭建 + Python 自定义模块 → 分享策略赚钱

### 核心使用场景

```
场景 1: 小白用户（跟单）
  打开 App → 策略市场 → 看到"动量轮动策略"月收益 8%
  → 点击"使用此策略" → 选择富途账户 → 设置投资金额 5 万
  → 策略开始自动运行 → 手机推送每次交易通知

场景 2: 进阶用户（说话就行）
  打开 App → 新建策略 → 打字：
    "RSI 低于 30 时买入 AAPL，仓位 20%，RSI 超过 70 全部卖出，止损 5%"
  → AI 自动生成策略 + 可视化卡片展示
  → 一键回测 3 年 → 年化 15%，夏普 1.2
  → 微调参数（拖滑块） → 确认 → 一键部署实盘

场景 3: 专业用户（模板 + 微调）
  打开 App → 策略模板库 → 选"海龟交易法"模板
  → 调整参数（滑块 / 数字输入）
  → 回测 → 优化 → 发布到策略市场 → 定价 ¥29.9/月
  → 其他用户订阅 → 每月收到分成

场景 4: 自然语言对话（Pro 专属）
  打开 App → AI 助手
  → "帮我设计一个适合震荡市的策略，主要做 TQQQ 和 SQQQ 的轮动"
  → AI 生成策略 → 解释逻辑 → 回测对比 → 用户确认后部署
```

### 关键架构决策记录 (ADR)

#### ADR-001: 桌面应用框架 → Electron（非 Tauri）

**决策**: 使用 Electron 而非 Tauri
**原因**:
- Electron 生态成熟，React + Ant Design 直接可用
- 富途 OpenD 是 TCP 协议，Node.js 处理很方便
- Tauri 的 Rust 后端增加开发复杂度
- 团队已有 Electron 经验
**权衡**: 包体较大（~150MB），但量化用户对磁盘不敏感

**修正**: 实际上可以考虑 Tauri 2.0 + React，因为：
- 包体小（~10MB vs ~150MB）
- 内存占用低（~80MB vs ~200MB）
- Rust 后端性能更好（回测引擎可以纯 Rust）
- Tauri 2.0 已经很成熟

**最终决策**: **Tauri 2.0 + React + TypeScript**

#### ADR-002: 策略引擎语言 → TypeScript DSL + WASM 回测核心

**决策**: 
- 策略表达：自定义 DSL（领域特定语言），JSON 序列化
- 回测核心：Rust 编译为 WASM，在 Tauri 后端运行
- 执行引擎：TypeScript，直连券商 API

**原因**:
- DSL 让策略可以序列化、分享、可视化编辑
- Rust 回测性能是 Python 的 10-50 倍
- TypeScript 执行引擎便于对接券商 API

#### ADR-003: 数据库 → SQLite（本地）+ PostgreSQL（云端）

**决策**: 
- 本地：SQLite（零配置，单文件）
- 云端：PostgreSQL（策略市场、用户数据）
- K线缓存：Parquet 文件（列式存储，查询快）

#### ADR-004: 策略编辑器 → 自然语言 + 表单 + 模板（三合一）

**决策**: 三种策略创建方式，用户自选：
1. **自然语言** — 打字描述策略，AI 自动生成
2. **表单模式** — 下拉菜单 + 滑块 + 数字输入（像填表一样简单）
3. **模板库** — 选经典策略模板，改参数就行

**否决方案**: 拖拽积木 / React Flow 节点编辑器
**否决原因**: 看起来酷但实际难用，用户测试普遍反馈"找不到在哪""连不上"

**原因**:
- 自然语言是最低门槛的交互方式
- 表单模式给想要精确控制的用户
- 模板覆盖 80% 的常见策略需求
- 三种方式生成的都是同一个 DSL，可以互相切换

## 5. 技术栈选型

### 前端（桌面应用）

| 层次 | 技术 | 理由 |
|------|------|------|
| 桌面框架 | **Tauri 2.0** | 小包体、低内存、Rust 后端 |
| UI 框架 | **React 18 + TypeScript** | 生态最大，组件丰富 |
| UI 组件库 | **Ant Design 5.x** | 专业金融风格，表格组件强 |
| 图表库 | **ECharts 5** + Lightweight Charts | K线图 + 策略收益曲线 |
| 策略编辑器 | **Monaco Editor** + Ant Design Form | 自然语言 + 表单 + 模板 |
| 状态管理 | **Zustand** | 轻量，适合复杂状态 |
| 国际化 | **i18next** | 中/英双语 |
| 样式 | **Tailwind CSS** + CSS Variables | 深色主题 |

### 后端（Tauri Rust 侧）

| 层次 | 技术 | 理由 |
|------|------|------|
| 回测引擎 | **Rust** | 极致性能，10年日线回测<1s |
| 数据解析 | **Polars (Rust)** | 比 Pandas 快 10-50x |
| K线存储 | **Parquet** | 列式存储，压缩好 |
| 策略 DSL | **自研 JSON DSL** | 可序列化、可可视化 |
| 券商协议 | **TCP (OpenD)** | 直连富途/moomoo |
| 本地 DB | **SQLite (rusqlite)** | 零配置 |

### 后端（TypeScript 侧）

| 层次 | 技术 | 理由 |
|------|------|------|
| API 层 | **Tauri Commands** | 前端调 Rust |
| 执行引擎 | **TypeScript (Deno)** | 策略逻辑执行 |
| 事件总线 | **自研 EventEmitter** | 模块间通信 |
| 定时任务 | **node-cron** | 策略调度 |
| 通知 | **WebSocket + 系统通知** | 实时推送 |

### 云端（Phase 2）

| 层次 | 技术 | 理由 |
|------|------|------|
| 框架 | **Hono (Cloudflare Workers)** | 边缘计算，全球加速 |
| 数据库 | **Neon (Serverless PostgreSQL)** | 按需伸缩 |
| 缓存 | **Upstash Redis** | Serverless Redis |
| 存储 | **Cloudflare R2** | 策略文件、回测报告 |
| 认证 | **Clerk** | 开箱即用 |
| 支付 | **Stripe** | 全球支付 |
| 推送 | **Novu** | 多通道通知 |

### 6.1 策略工坊 (Strategy Workshop)

**职责**: 策略的创建、编辑、回测、优化

**三种创建方式**:

```
┌─────────────────────────────────────────────┐

│                                             │
```

### 6.2 数据中心 (Data Center)

**职责**: 行情数据的采集、存储、清洗、分发

**子模块**:

### 6.4 风控引擎 (Risk Engine)

**职责**: 交易前风控检查 + 实时监控

**规则**:

```
交易前检查（Pre-Trade）:
  □ 单笔仓位 ≤ 总资金 X%（可配置）
  □ 总持仓 ≤ 总资金 Y%（可配置）
  □ 单日最大亏损 ≤ Z（可配置）
  □ 单品种最大仓位 ≤ N 股/手
  □ 相关性检查（避免高相关品种重仓）
  □ 黑名单检查（ST股、退市预警等）

实时监控（Real-Time）:
  □ 最大回撤监控（超阈值自动减仓）
  □ 异常波动检测（闪崩保护）
  □ 净值曲线偏离检测
  □ 滑点监控（实际成交价 vs 信号价）
  □ 延迟监控（信号到下单的时间差）
```

### 7.4 回测引擎设计

```
输入:
  - 策略 DSL (JSON)
  - 回测区间 (start_date, end_date)
  - 初始资金
  - 手续费率
  - 滑点模型

处理流程:
  1. 加载历史 K 线数据 (Parquet)
  2. 按时间轴逐 bar 推进
  3. 每根 bar:
     a. 更新指标值 (SMA, RSI, MACD...)
     b. 检查信号条件
     c. 生成交易信号
     d. 风控检查
     e. 模拟下单 (考虑滑点、手续费)
     f. 更新持仓、资金
     g. 记录日志
  4. 输出回测报告

输出:
  - 收益曲线 (净值曲线)
  - 年化收益率
  - 夏普比率
  - 最大回撤
  - Calmar 比率
  - 胜率
  - 盈亏比
  - 交易明细
  - 月度收益热力图
  - 基准对比 (vs SPY/QQQ)

性能目标:
  - 10 年日线回测 (单品种): < 500ms
  - 10 年日线回测 (100 品种): < 5s
  - 1 年分钟线回测 (单品种): < 2s
```

```typescript
interface RiskRule {
  id: string;
  name: string;
  level: 'global' | 'strategy' | 'order';
  check(context: TradeContext): RiskCheckResult;
  action: 'reject' | 'warn' | 'reduce' | 'pause';
}

// 内置规则
const BUILT_IN_RULES: RiskRule[] = [
  {
    id: 'max_single_position',
    name: '单品种最大仓位',
    level: 'global',
    check: (ctx) => {
      const posPct = ctx.positionValue / ctx.totalAssets;
      if (posPct > ctx.config.maxSinglePosition) {
        return { pass: false, reason: `仓位 ${posPct.toFixed(1)}% 超限` };
      }
      return { pass: true };
    },
    action: 'reject'
  },
  {
    id: 'daily_loss_limit',
    name: '单日最大亏损',
    level: 'global',
    check: (ctx) => {
      const dailyPnlPct = ctx.todayPnl / ctx.yesterdayTotal;
      if (dailyPnlPct < -ctx.config.dailyLossLimit) {
        return { pass: false, reason: `今日亏损 ${dailyPnlPct.toFixed(1)}% 超限` };
      }
      return { pass: true };
    },
    action: 'pause'  // 暂停所有策略
  },
  // ... 更多规则
];
```

## 12. 安全设计

### 12.1 本地安全

| 威胁 | 防护 |
|------|------|
| 交易密码泄露 | 加密存储（AES-256），运行时解密 |
| 策略 DSL 被篡改 | 签名验证 |
| 数据库被读取 | SQLite 加密（SQLCipher） |
| 进程注入 | Tauri 安全模型 |
| 恶意策略 | 策略沙箱执行 |

### 12.2 网络安全

| 威胁 | 防护 |
|------|------|
| MITM 攻击 | TLS 加密通信 |
| API Key 泄露 | 本地存储，不上云 |
| DDoS | Cloudflare 防护 |
| XSS | CSP 头 + React 自动转义 |

### 12.3 交易安全

| 威胁 | 防护 |
|------|------|
| 乌龙指 | 价格合理性检查 |
| 死循环下单 | 频率限制（每分钟最多 N 单） |
| 超额交易 | 资金/仓位预检查 |
| 策略失控 | 紧急停止按钮 + 自动熔断 |

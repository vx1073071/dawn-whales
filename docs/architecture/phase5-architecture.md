## 2. Multi-Timeframe 架构

### 数据流

```
1m K线 (原始数据)
    │
    ├──→ 5m 聚合 (5 bars → 1 bar)
    ├──→ 15m 聚合 (15 bars → 1 bar)
    ├──→ 30m 聚合 (30 bars → 1 bar)
    ├──→ 1h 聚合 (60 bars → 1 bar)
    ├──→ 4h 聚合 (240 bars → 1 bar)
    └──→ 1d 聚合 (1440 bars → 1 bar)

信号融合:
    1m信号 ──┐
    5m信号 ──┤
    15m信号 ─┼──→ [融合引擎] ──→ 综合信号
    30m信号 ─┤      │
    1h信号 ──┤   majority / weighted / any
    4h信号 ──┤
    1d信号 ──┘
```

### 融合模式

| 模式 | 逻辑 | 适用场景 |
|-----|------|---------|
| majority | >50% 周期同向 | 趋势确认 |
| weighted | 高周期权重更大 | 稳健策略 |
| any | 任一周期触发 | 敏感策略 |

   - 7 周期聚合

### 安全机制

3. **频率限制**: 每分钟最大订单数
4. **异常熔断**: 连续失败自动切换模拟盘
5. **审计日志**: 所有操作完整记录

## 6. 技术决策记录

### ADR-5.0.1: 多周期信号融合策略

**决策**: 采用 3 种融合模式 (majority/weighted/any)  
**理由**: 覆盖不同策略风格  
**后果**: 用户可根据市场状态选择

### ADR-5.0.2: VaR 计算方法

**决策**: 历史模拟法为主，参数法为辅  
**理由**: 不假设分布，适应厚尾  
**后果**: 需要足够历史数据 (>100 样本)

### ADR-5.0.3: Live Trading 安全优先

**决策**: 模拟盘优先，实盘需双重确认  
**理由**: 资金安全第一  
**后果**: 用户体验略降，但风险可控

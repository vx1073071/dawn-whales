## 版本管理

### 语义化版本

quant-moo 遵循**语义化版本** (Semantic Versioning):

```
MAJOR.MINOR.PATCH

MAJOR: 不兼容的 API 变更
MINOR: 向后兼容的功能新增
PATCH: 向后兼容的问题修复
```

### 版本号规则

| 版本类型 | 说明 | 示例 |
|---------|------|------|
| Alpha | 内部测试版 | v1.0.0-alpha.1 |
| Beta | 公开测试版 | v1.0.0-beta.1 |
| RC | 发布候选版 | v1.0.0-rc.1 |
| GA | 正式发布版 | v1.0.0 |

### 分支策略

```
main (v1.0.0)
  ↑
  │ merge
  │
develop (v1.1.0-dev)
  ↑
  │ merge
  │
feature/* (feature branches)
```

- **main**: 稳定版本，只接受 release 分支合并
- **develop**: 开发版本，接受 feature 分支合并
- **feature/***: 功能分支，从 develop 创建

## 回滚策略

### 回滚场景

| 场景 | 严重程度 | 回滚策略 |
|-----|---------|---------|
| 安装失败 | 高 | 提供旧版本下载 |
| 启动崩溃 | 高 | 自动回滚 + 日志收集 |
| 功能异常 | 中 | 热修复补丁 |
| 性能下降 | 中 | 配置回滚 |
| 数据丢失 | 高 | 数据恢复 + 版本回滚 |

### 回滚步骤

#### 步骤 1: 评估问题

```bash
# 收集日志
tail -f ~/.quant-moo/logs/error.log

# 检查版本
quant-moo --version

# 检查配置
cat ~/.quant-moo/config.json
```

#### 步骤 2: 决定回滚

**回滚条件**:
- 影响 > 50% 用户
- 无法热修复
- 数据安全风险

#### 步骤 3: 执行回滚

```bash
# 下载旧版本
wget https://github.com/vx1073071/quant-moo/releases/download/v0.13.0/quant-moo-Setup-0.13.0.exe

# 卸载当前版本
npm uninstall -g quant-moo

# 安装旧版本
./quant-moo-Setup-0.13.0.exe

# 恢复数据
quant-moo --restore-backup
```

#### 步骤 4: 通知用户

**通知内容**:
- 问题说明
- 回滚原因
- 回滚步骤
- 后续计划

### 数据备份

**自动备份**:
- 每次启动前自动备份
- 备份位置: `~/.quant-moo/backups/`
- 保留最近 7 天

**手动备份**:
```bash
# 备份配置
quant-moo --backup-config

# 备份数据
quant-moo --backup-data

# 恢复备份
quant-moo --restore-backup <backup-id>
```
